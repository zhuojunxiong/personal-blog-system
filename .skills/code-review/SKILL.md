# Code Review Skill

状态：v1.0 课程交付

用途：在提交代码前或完成功能模块后，对当前分支变更做系统性审查，记录发现到正式 Review 文档中。

## 触发短语

说出以下任一即可触发本 Skill：
- "review this" / "code review" / "做一次代码Review"
- "提交前检查" / "这个功能写完了，帮我审查"

## 触发场景

- 完成一个 CR 对应的功能实现后
- `git commit` 之前做最后一次检查
- 合并到 `work/v1.0-course-delivery` 之前
- 准备交付材料，需要更新 `docs/10_代码Review记录.md` 时

## 前置检查（必须先执行）

```bash
git branch --show-current          # 确认在 work/v1.0-course-delivery
git diff --stat                    # 查看变更文件清单
git diff                           # 查看具体变更内容
```

## 工作步骤

### 1. 读入上下文
- 读取 `AGENTS.md`，确认当前分支、阶段定位和禁止事项。
- 读取 `docs/10_代码Review记录.md`，了解历史 Review 结论和遗留问题。
- 如有关联 CR，读取 `docs/change-requests/CR-XXX-*.md` 确认需求边界。

### 2. 逐文件审查（按以下维度）
| 维度 | 检查要点 |
| --- | --- |
| 正确性 | 逻辑是否有 bug；边界条件（空值、越界、并发）是否处理；路由/模型/模板是否一致 |
| 安全性 | CSRF 保护是否覆盖变更路由；SQLAlchemy 是否使用参数化查询；用户输入是否校验 |
| 性能 | 是否存在 N+1 查询；是否缺少数据库索引；视图函数是否有不必要的循环 |
| 文档对齐 | 变更是否与 `docs/07_需求规格说明书.md` 一致；与 `docs/08_概要设计说明书.md` 的架构描述是否冲突 |

### 3. 判定风险等级
- **高**：涉及认证/权限/数据写入/SQL 拼装/文件操作
- **中**：涉及路由逻辑/查询优化/模板渲染
- **低**：仅涉及文档/注释/静态资源

### 4. 写入 Review 记录
追加到 `docs/10_代码Review记录.md`，使用以下模板：

```markdown
## Review 记录 —— [日期] [审查人]

- **分支**：work/v1.0-course-delivery
- **关联 CR**：[编号或 N/A]
- **变更范围**：[文件清单，从 git diff --stat 提取]
- **主要发现**：
  1. [发现项，标注严重程度]
- **测试状态**：[已通过 / 未执行 / 部分通过]
- **风险等级**：[高/中/低]
- **需补材料**：[缺失的测试/文档/ADR]
- **是否建议提交**：[是 / 否（附理由）]
```

## 常用 Git 命令速查

```bash
git diff --stat                    # 变更文件概览
git diff app/                      # 只看 app/ 目录的变更
git log --oneline -5               # 最近 5 次提交
git show <commit> --stat           # 某次提交的变更范围
```

## 禁止事项

1. 不直接重构代码——只提建议，不改代码。
2. 不伪造测试通过——未执行就写"未执行"。
3. 不把建议写成已完成。
4. 不读取或修改 `software-practice-records`。
