# V0.5 版本迭代文档

> 文档类型：版本迭代总结
> 项目名称：多用户知识专栏博客系统
> 当前版本：V0.5
> 技术栈：Flask + Jinja2 + Flask-Login + SQLAlchemy + SQLite + DeepSeek API
> 版本主题：真实 AI 接入 + 安全加固 + 写作体验升级

## 一、版本背景

V0.4.1 完成了界面与交互链路的统一重构，系统具备了稳定的课程演示能力，但 AI 功能仍处于占位状态——写文章页的 AI 面板只会提示"后续版本开放"，并不产生真实价值。

V0.5 的核心目标就是**打通 AI 链路**：从"假 AI 占位"升级为"可配置的真实 AI 服务"，让摘要、标签、润色、问答等功能真正帮助写作者。同时补齐前一版本遗留的安全问题（SECRET_KEY 硬编码、无 CSRF 保护等）。

## 二、版本定位

> 在 V0.4.1 的稳定界面基础上，接入 DeepSeek API 实现 6 个真实 AI 写作辅助功能，并完成安全加固，使系统成为一个安全、可用、可演示的多用户知识创作平台。

本版本不是架构迁移版本，也不是功能膨胀版本。

本版本解决的核心问题：

1. AI 功能全是占位提示，没有实际价值
2. SECRET_KEY 硬编码在代码中
3. 所有 POST 表单缺少 CSRF 保护
4. datetime.utcnow() 在 Python 3.12+ 已废弃
5. AI 调用使用 stdlib urllib，SSL 处理不够稳健
6. 中文标题检测只支持一至六，范围太窄
7. 文档分散、路径写死 Windows PowerShell、缺少统一使用教程

## 四、AI 功能详解

### 4.1 架构设计

```
写文章页面 (write.html)
    │
    ├── AI 面板按钮 → fetch POST → /ai/summary|tags|polish|outline|titles
    │                                      │
    └── AI 问答框   → fetch POST → /ai/chat  │
                                             │
                                    AIService (app/ai/services.py)
                                             │
                                    requests → DeepSeek API
                                             │
                                    AiLog ← 记录到 SQLite
```

- AI 路由使用 `@csrf.exempt` 豁免 CSRF（因为走 JSON + fetch）
- AI 接口不配置 API Key 时返回友好提示，不产生远程请求
- 每个场景独立配置 `(max_tokens, temperature)`
- 所有 AI 调用写入 `AiLog` 表

### 4.2 六个 AI 功能

| 功能 | 路由 | 系统提示词要点 | max_tokens | temp |
|------|------|---------------|------------|------|
| **生成摘要** | `/ai/summary` | 结构化输出：核心观点 + 3-5 条要点 + 实践价值，200 字内 | 1500 | 0.3 |
| **推荐标签** | `/ai/tags` | 混合推荐技术词 + 方法词 + 场景词，3-8 个 | 800 | 0.3 |
| **润色正文** | `/ai/polish` | 逐段编辑：修正语病、调整段落、解释术语、保留标题层级 | 3000 | 0.7 |
| **提取大纲** | `/ai/outline` | 分析文章结构，提取章节标题（缩进列表） | 2000 | 0.3 |
| **标题建议** | `/ai/titles` | 生成 5 个候选标题：3 个务实型 + 2 个吸引型 | 800 | 0.7 |
| **文章问答** | `/ai/chat` | 结构化回答：核心结论 → 展开说明 → 延伸思考，400 字内 | 2000 | 0.5 |

### 4.3 提示词设计原则

- **摘要**：低温度（0.3），要求结构化输出，避免"本文""作者"等套话开头
- **标签**：低温度（0.3），要求技术词、方法词、场景词混合，模拟读者搜索行为
- **润色**：高温度（0.7），增加表达多样性；保留标题和代码块不动
- **大纲**：低温度（0.3），要求准确识别或归纳文章结构
- **标题**：高温度（0.7），务实型和吸引型各半，增加创意
- **问答**：中温度（0.5），平衡准确与灵活；改进建议从结构、论证、可读性三维度给出

### 4.4 默认配置

```python
AI_MODEL = "deepseek-chat"     # DeepSeek 最新旗舰模型
AI_BASE_URL = "https://api.deepseek.com"
AI_MAX_TOKENS = 2000

```

可通过环境变量覆盖：

```bash

```

### 4.5 与 V0.4.1 的 AI 差异

| 维度 | V0.4.1 | V0.5 |
|------|--------|------|
| AI 调用 | 占位提示 | 真实 DeepSeek API |
| 功能数量 | 3 个按钮 + 问答框 | 5 个按钮 + 问答框 |
| 提示词 | 无 | 结构化、场景化 |
| 参数调优 | 无 | 每场景独立 temperature 和 max_tokens |

## 五、安全加固

### 5.1 SECRET_KEY

**之前**（config.py）：
```python
SECRET_KEY = "dev-secret-key-change-before-production"
```

**之后**：
```python
SECRET_KEY = os.getenv("SECRET_KEY") or secrets.token_hex(32)
```

优先从环境变量读取，否则用 `secrets.token_hex(32)` 随机生成 64 字符密钥。

### 5.2 CSRF 保护

集成 Flask-WTF CSRFProtect，全站 POST 请求需要 CSRF token。

实现方案：
1. `app/extensions.py` 初始化 `CSRFProtect`
2. `config.py` 新增 `WTF_CSRF_SECRET_KEY` 配置
3. `app/__init__.py` 注册 CSRFProtect，添加 CSRF 错误处理器（400 错误自动提示"表单验证已过期"）
4. `base.html` 和 `admin/base.html` 添加 `<meta name="csrf-token">` 和 JS 自动注入脚本
5. JS 自动向所有 `<form method="post">` 注入隐藏字段 `<input name="csrf_token">`
6. JS 自动为所有 `fetch()` 请求添加 `X-CSRFToken` 请求头
7. AI JSON 接口通过 `@csrf.exempt` 豁免

**效果**：无需修改任何单个模板的 `<form>` 标签，全站自动获得 CSRF 保护。

### 5.3 CSRF 错误处理

```
CSRF token 缺失/无效 → 400 Bad Request
    → 自定义 errorhandler 拦截
    → flash("表单验证已过期，请刷新页面后重试。")
    → redirect(referrer)
```

## 六、代码质量改进

### 6.1 datetime.utcnow → utcnow()

Python 3.12+ 中 `datetime.utcnow()` 已标记废弃。新增 `utcnow()` 工具函数：

```python
def utcnow():
    """Return a naive UTC datetime compatible with SQLite, safe for Python ≥3.12."""
    return datetime.now(timezone.utc).replace(tzinfo=None)
```

影响文件：
- `app/services.py` — 新增 `utcnow()`
- `app/models.py` — 全部 22 处 `datetime.utcnow` → `utcnow`
- `app/article/services.py` — 2 处替换
- `scripts/demo_data.py` — 1 处替换

### 6.2 urllib → requests

AI 服务的 HTTP 调用从 stdlib `urllib.request` 切换为 `requests` 库：

- SSL 验证更可靠（certifi 证书包）
- 异常处理更清晰（Timeout、HTTPError、ConnectionError、RequestException）
- 请求构造更简洁（`requests.post(url, json=payload, headers=headers)`）

### 6.3 中文标题检测

**之前**：只支持 `一、` 到 `六、`，且任何以 `：` 结尾的行都被判为标题。

**之后**：
- 使用正则 `_CN_NUMBERED` 匹配一至二十序号（`一、` 到 `二十、`）
- 使用正则 `_CN_LABEL` 匹配 2-8 字中文短标签（如 `关键词：`）
- 移除过宽的冒号结尾匹配

### 6.4 依赖声明

`requirements.txt` 从 3 个依赖补全为 8 个，全部固定版本：

```

```
