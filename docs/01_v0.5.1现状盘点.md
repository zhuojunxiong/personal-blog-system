## 1. 当前项目定位

当前项目是一个基于 Flask 的多用户知识专栏博客系统。根据 `AGENTS.md` 和 `README.md`，项目定位已经从早期“管理员写、游客看”的个人博客，演进为“普通用户可注册、创建专栏、发布文章、阅读和交流知识内容”的多用户知识创作平台。

当前代码支持：

- 游客浏览首页、文章、分类、标签、专栏、作者主页和搜索结果。
- 普通用户注册、登录、编辑资料、管理个人专栏、发布文章、评论、点赞、收藏。
- 管理员登录后台并管理用户、文章、专栏、分类、标签、评论和 AI 状态页。
- 写作页和接口层接入 AI 摘要、标签推荐、润色、问答、大纲、标题建议和智能搜索相关能力。

需人工确认：

## 6. 当前数据库模型

当前模型集中在 `app/models.py`。

### 6.1 User

表名：`users`

主要字段：

- `id`
- `username`
- `email`
- `password_hash`
- `nickname`
- `role`
- `status`
- `bio`
- `avatar`
- `created_at`
- `updated_at`

主要能力：

- 密码哈希设置与校验。
- `is_active` 基于 `status == "active"`。
- `is_admin` 基于 `role == "admin"`。

### 6.2 BlogColumn

表名：`blog_columns`

主要字段：

- `id`
- `user_id`
- `name`
- `description`
- `status`
- `created_at`
- `updated_at`

关系：

- 多个专栏属于一个用户。
- 一个专栏可关联多篇文章。

### 6.3 Category

表名：`categories`

主要字段：

- `id`
- `name`
- `description`
- `sort_order`
- `created_at`
- `updated_at`

关系：

- 一个分类可关联多篇文章。

### 6.4 Tag 与 ArticleTag

表名：

- `tags`
- `article_tags`

`Tag` 主要字段：

- `id`
- `name`
- `created_at`
- `updated_at`

`ArticleTag` 主要字段：

- `article_id`
- `tag_id`
- `created_at`

关系：

- 文章和标签是多对多关系。

### 6.5 Article

表名：`articles`

主要字段：

- `id`
- `title`
- `slug`
- `summary`
- `content`
- `status`
- `user_id`
- `column_id`
- `category_id`
- `author`
- `view_count`
- `like_count`
- `favorite_count`
- `created_at`
- `updated_at`
- `published_at`

状态：

- `draft`
- `published`

关系：

- 文章可属于用户、专栏、分类。
- 文章可关联多个标签。
- 文章可关联评论和 AI 日志。

### 6.6 Comment

表名：`comments`

主要字段：

- `id`
- `article_id`
- `user_id`
- `nickname`
- `email`
- `content`
- `status`
- `created_at`
- `updated_at`

状态：

- `pending`
- `approved`
- `hidden`

### 6.7 Like

表名：`likes`

主要字段：

- `id`
- `user_id`
- `article_id`
- `created_at`

约束：

- `user_id + article_id` 唯一，防止同一用户重复点赞同一文章。

### 6.8 Favorite

表名：`favorites`

主要字段：

- `id`
- `user_id`
- `article_id`
- `created_at`

约束：

- `user_id + article_id` 唯一，防止同一用户重复收藏同一文章。

### 6.9 AiLog

表名：`ai_logs`

主要字段：

- `id`
- `article_id`
- `scene`
- `input_text`
- `ai_output`
- `adopted_result`
- `is_adopted`
- `problem_found`
- `created_at`

说明：

- 模型层存在 AI 日志表。
- 是否所有 AI 接口都完整写入日志，需人工确认。

## 14. 当前代码结构问题

当前可见问题如下：

1. `errors/400.html` 缺失。
   - `app/__init__.py` 注册了 400 错误处理，但模板目录没有 `app/templates/errors/400.html`。
   - CSRF 失败等 400 场景可能在渲染错误页时再次出错。

2. v041 模板与 public 模板并存。
   - `/`、`/home`、文章详情、搜索页使用 `v041/` 模板。
   - 其他公开页仍使用 `public/` 模板。
   - 当前结构反映了版本演进，但长期维护时可能造成页面风格和逻辑分散。

3. 管理端文章和用户个人写作共用部分服务逻辑，但入口分散。
   - `app/article/routes.py` 处理后台文章。
   - `app/user/routes.py` 处理普通用户写作。
   - 权限规则目前散落在路由层和服务调用前后，后续扩展时需谨慎。

4. 测试脚本位于根目录且会操作真实配置数据库。
   - `test_e2e.py` 直接使用 `create_app()` 和默认配置。
   - 未见独立测试数据库配置。
   - 可能影响本地演示数据。

5. `README.md` 写“暂未实现自动化测试套件”，但仓库存在 `test_e2e.py`。
   - 更准确说法可能是“存在自写 E2E 脚本，但尚未形成规范自动化测试套件”。
   - 需人工确认 README 是否需要更新。

   - 若不统一，后续需求、设计和验收可能引用过期事实。

   - 本次未启动项目。
   - README 启动流程依赖虚拟环境、依赖安装、数据库初始化和演示数据脚本。
   - 任一环节失败都会影响课程演示。

   - `test_e2e.py` 使用默认应用配置，可能写入当前 SQLite 数据库。
   - 若直接在演示库运行测试，可能产生或删除数据。

   - 缺失 `errors/400.html`，400 错误处理路径可能异常。

5. 外部 AI 依赖风险。
   - AI 功能依赖 `AI_API_KEY`、网络和 DeepSeek/OpenAI 兼容接口。
   - 未配置或接口异常时，演示效果会受影响。

   - `V5.1` 可能被误读为大版本 5.1，而 `v0.5.1` 是当前治理阶段。
   - 对课程交付、文档封面和验收口径有影响。

7. 治理材料不完整风险。
   - ADR、测试报告、代码 Review、AI 协作记录仍未形成正式正文。
   - 如果直接交付，工程化治理证据不足。

8. 数据库演进风险。
   - 无迁移体系时，模型字段调整可能要求重建数据库。
   - 对已有演示数据和用户数据有潜在破坏风险。

9. 权限边界回归风险。
   - 当前权限控制分散在多个 routes 和装饰器中。
   - 后续新增入口时若未复用规则，可能出现越权访问。

    - 历史文档中包含多个版本目标和总结。
    - 后续正式文档必须继续区分“当前代码已实现”“历史文档声称完成”“计划中”“需人工确认”。
