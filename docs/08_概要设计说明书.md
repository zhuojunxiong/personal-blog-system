## 3. 当前总体架构

当前系统是服务端渲染单体应用，整体结构为：

```text
浏览器
  -> Flask Blueprint 路由
  -> Flask-Login / admin_required / CSRFProtect
  -> Service 或 SQLAlchemy 查询
  -> SQLAlchemy Model
  -> SQLite
  -> Jinja2 Template
  -> HTML 或 JSON 响应
```

当前架构风格可以概括为“轻量 MVC + Service 辅助”：

| 架构角色 | 当前实现 | 说明 |
|---|---|---|
| Controller | `app/*/routes.py` | 接收请求、校验登录和权限、调用 service 或 ORM、返回模板或 JSON。 |
| Model | `app/models.py` | 定义用户、文章、知识合集、分类、标签、评论、点赞、收藏、AI 日志等模型，并保存 Markdown 主页和搜索用 AI 摘要。 |
| View | `app/templates/` | 使用 Jinja2 渲染前台、个人中心、后台和错误页。 |
| Service | `app/*/services.py`、`app/services.py` | 承载可复用业务逻辑、查询逻辑、AI 调用和部分事务。 |
| Static | `app/static/css/`、`app/static/js/` | 承载全局样式、v041 样式和原生 JS 交互。 |

当前系统不是微服务，不是前后端完全分离，不依赖独立前端构建体系，也未引入任务队列、搜索引擎或生产级数据库。

## 7. Blueprint 路由结构

| Blueprint | URL 组织 | 主要入口 | 关联需求 |
|---|---|---|---|
| `public` | 无统一前缀 | `/`、`/home`、`/discover`、`/articles`、`/articles/<slug>`、`/categories`、`/tags`、`/search` | F001-F007, F035 |
| `auth` | 无统一前缀 | `/login`、`/admin/login`、`/register`、`/logout` | F008-F009 |
| `admin` | `/admin` | `/admin/` | F021 |
| `dashboard` | `/admin` | `/admin/dashboard` | F021 |
| `article` | `/admin/articles` | 后台文章列表、新增、编辑、删除 | F016 |
| `category` | `/admin/categories` | 后台分类列表、新增、编辑、删除 | F023 |
| `tag` | `/admin/tags` | 后台标签列表、新增、编辑、删除 | F024 |
| `comment` | 混合 | `/articles/<slug>/comments`、`/articles/<slug>/like`、`/articles/<slug>/favorite`、`/admin/comments` | F017-F020 |
| `column` | 混合 | `/columns`、`/columns/<id>`、`/my/columns`、`/admin/columns` | F005, F013, F025 |
| `ai` | 混合 | `/admin/ai`、`/ai/status`、`/ai/summary`、`/ai/tags`、`/ai/polish`、`/ai/chat`、`/ai/outline`、`/ai/titles`、`/ai/search`、`/ai/research`、`/ai/search-summary` | F026-F034, CR009-F007, CR009-F008 |
| `user` | 混合 | `/users/<id>`、`/profile`、`/settings`、`/write`、`/my/articles/...`、`/admin/users` | F006, F010-F012, F014-F015, F022 |

设计说明：

1. 后台路由分散在多个业务模块中，统一依赖 `admin_required()` 做管理员权限保护。
2. 个人创作路由主要在 `user` 模块中，复用 `ArticleService` 和相关模型。
3. 评论、点赞、收藏入口归入 `comment` 模块，其中点赞和收藏业务复用 `ArticleService`。
4. AI 写作接口面向登录用户写作场景，AI 搜索接口作为公开搜索增强入口存在。
5. AI JSON 接口存在 CSRF 豁免实现，是否需要进一步收敛安全口径需后续人工确认。

当前数据模型集中在 `app/models.py`，以 SQLAlchemy 模型定义。主要模型如下：

| 模型 | 表 | 核心职责 | 关联需求 |

| `ArticleTag` | `article_tags` | 文章与标签的多对多关联。 | F004, F014, F024 |
| `Article` | `articles` | 文章标题、摘要、正文、状态、阅读量、作者、分类、专栏。 | F001-F007, F014-F016, F019-F020 |
| `Comment` | `comments` | 评论内容、评论状态、文章和用户关联。 | F017-F018 |
| `Like` | `likes` | 用户与文章点赞关系，避免重复点赞。 | F019 |
| `Favorite` | `favorites` | 用户与文章收藏关系，避免重复收藏。 | F020 |
| `AiLog` | `ai_logs` | AI 调用场景、输入、输出和基础日志字段。 | F033-F034 |

核心关系如下：

```text
User 1 ── * Article
User 1 ── * BlogColumn
BlogColumn 1 ── * Article
Category 1 ── * Article
Article * ── * Tag，通过 ArticleTag
Article 1 ── * Comment
User 1 ── * Comment
User * ── * Article，通过 Like
User * ── * Article，通过 Favorite
Article 1 ── * AiLog
```

数据设计边界：

1. 当前没有 `ReadingHistory` 模型，F012 中真实最近阅读属于部分实现或 N007 后续候选，不能写成当前已实现。
2. `AiLog` 基础模型和写入存在，但 F033 的采纳结果、是否采纳、问题标记等闭环需补需求和设计，不能写成完整闭环已实现。
3. 当前没有关注、私信、付费、广告、热榜、问答社区等模型，不能把这些能力写成当前架构。
4. 若后续新增 `ReadingHistory` 或 AI 日志闭环字段，需要先完成需求确认、概要/详细设计、ADR 和数据库变更策略确认。

## 14. 主要业务流程

### 14.1 游客浏览与阅读

```text
游客访问首页、发现页、文章列表、分类、标签、专栏或作者主页
-> public / column / user 路由
-> Service 或 ORM 查询公开内容
-> SQLite 返回数据
-> Jinja2 模板渲染
-> 浏览器展示
```

文章详情流程：

```text
GET /articles/<slug>
-> 查询已发布文章
-> 增加阅读量
-> 组织正文块和目录信息
-> 渲染阅读页
```

关联需求：F001-F007。阅读页 AI 提示对应 F035 后续计划，不是当前 AI 阅读助手。

### 14.2 注册登录

```text
用户提交注册或登录表单
-> auth 路由
-> AuthService / User 密码校验
-> Flask-Login 写入登录态
-> 跳转个人空间、公开页或后台
```

关联需求：F008-F009、F041。

### 14.3 用户创作

```text
登录用户进入 /write
-> 查询分类、标签、个人专栏
-> 渲染写作页

用户提交文章
-> 校验作者身份和表单数据
-> ArticleService 创建或更新文章
-> 保存草稿或发布文章
-> 跳转编辑页或文章详情页
```

关联需求：F013-F015、F026-F031。

### 14.4 评论、点赞、收藏

```text
登录用户提交评论
-> 创建 pending 评论
-> 管理员后台审核、隐藏或删除
```

```text
登录用户点赞或收藏
-> 查询 Like/Favorite 是否存在
-> 存在则取消，不存在则新增
-> 更新计数并返回结果
```

关联需求：F017-F020。

### 14.5 后台治理

```text
管理员访问后台
-> admin_required 校验
-> 对应后台路由调用 service 或 ORM
-> 渲染后台模板
-> 提交管理操作后写入数据库
```

关联需求：F016、F018、F021-F025、F034、F042。

### 14.6 AI 写作辅助

```text
登录用户在写作页触发 AI 操作
-> 前端 POST JSON 到 /ai/*
-> 路由校验输入和用户上下文
-> AIService 组装 OpenAI 兼容请求
-> requests 调用远程 AI 服务
-> 成功或失败后写入基础 AiLog
-> 返回 JSON 给前端
```

关联需求：F026-F031、F033、F044-F046。真实远程 API 调用需配置 API Key 后验证。

### 14.7 AI 智能搜索

```text
用户提交 AI 搜索
-> v041.js POST /ai/search
-> AIService 进行意图理解、关键词扩展、SQL 候选检索、AI 重排序
-> 失败时降级
-> 前端渲染 AI 搜索结果或回退传统搜索
```

关联需求：F032、F033、F045-F046。真实调用、失败降级和结果质量需后续验证。

## 15. 异常处理设计

当前异常处理设计包括：

| 异常类型 | 当前设计 | 关联需求 |
|---|---|---|
| 未登录访问登录态功能 | 通过 Flask-Login 引导登录或拒绝。 | F008-F015, F017-F020 |

| AI 搜索失败 | 前端或服务端保留降级路径，回退传统搜索或候选结果。 | F032, F045-F046 |

## 18. 方案 B 下的受控局部重构边界

ADR-002 已采纳方案 B：保留当前 Flask + Jinja2 + SQLAlchemy + SQLite 技术栈，在测试保护、需求确认和 ADR 约束下做受控局部重构。

### 18.1 可以评估的局部重构方向

| 方向 | 可能收益 | 前置条件 |
|---|---|---|
| 路由边界整理 | 降低公开、个人、后台路由混合带来的理解成本。 | 明确影响范围、补路由测试、必要时补 ADR。 |
| Service 收敛 | 减少路由中直接 ORM 查询，提高复用和可测性。 | 先覆盖搜索、个人空间、写作等关键路径测试。 |
| 模型拆分 | 模型继续增加时降低单文件维护压力。 | 处理导入、迁移、测试和回滚方案；需 ADR。 |
| CSS/JS 分层 | 改善视觉一致性和前端资源维护。 | 先完成视觉验收，避免无目标整理。 |
| AI Provider 抽象 | 支撑多模型或多 Provider 扩展。 | 先确认多 Provider 是真实需求，不为假想扩展抽象。 |
| AI 日志闭环设计 | 补齐采纳结果、问题标记和质量追踪。 | 先完成 N006 需求和数据设计。 |
| 事务边界梳理 | 降低复杂写入时的提交分散风险。 | 先识别具体问题和回归测试范围。 |

### 18.2 当前明确禁止或暂缓的事项

1. 不更换 Flask、Jinja2、SQLAlchemy、SQLite 主技术栈。
2. 不进行前后端完全分离。
3. 不把当前分支作为 v0.6 功能开发分支直接扩展新功能。
4. 不重新开发 v1.0。
5. 不默认开启新架构实验分支。
6. 不在缺少需求、设计、测试保护和 ADR 时做模型大拆分、路由大挪动或数据库结构变化。
7. 不把 F026-F032 的接口存在写成真实 API 调用已通过。
8. 不把 F033 的基础日志写入写成 AI 采纳闭环已完成。

### 18.3 局部重构执行条件

后续若进入方案 B 的局部重构，至少应满足：

1. 有明确需求或缺陷触发，例如 F012、F033、F048、N006、N007、N011。
2. 已补相关测试保护，或明确记录未能测试的原因和风险。
3. 涉及架构边界、数据库结构或技术策略时先写 ADR。
4. 修改前后检查 `git diff`，确保没有业务代码误改和无关重构。
5. 完成后补测试记录、Review 记录和必要的 AI 协作记录。

7. F033 AI 日志闭环是否进入后续实现，需先完成 N006 需求和设计。
8. F012 是否新增真实最近阅读 `ReadingHistory`，需按 N007 人工确认。
9. F048 视觉一致性需按 N008 做浏览器验收。
10. 当前分支仍是工程治理分支，不是 v0.6 功能开发分支。
11. 产品重新基线化之后，下一实现版本选择 v0.6、v0.7 还是 v1.0，需人工确认。
12. 当前周期继续禁止技术栈替换、前后端分离、大规模重写和无关重构，除非未来另行确认并形成新的 ADR。

## 阶段性结论

当前概要设计以 Flask + Jinja2 + SQLAlchemy + SQLite 单体架构为基础，已经能够支撑 F001-F025 的游客浏览、用户创作、互动和后台治理主业务闭环，也为 F026-F034 的 AI 写作辅助、AI 搜索和 AI 状态管理提供接口与基础日志支撑。

当前主要问题不是必须换栈或重写，而是 F026-F033 的真实 AI 调用与日志闭环验证、F036-F050 的启动测试、错误页、视觉一致性、README 和正式文档链路证据仍需补齐。后续应遵守 ADR-002 的方案 B：保留当前技术栈，在测试保护、需求确认和 ADR 约束下做受控局部重构，并在产品重新基线化之后再决定下一实现版本。
