## 1. 协作背景

当前项目采用半自动工程化开发体系，即“统一主仓库 + Agent + Skill + ADR + Git 小步提交 + 测试记录 + Review 记录 + AI 协作记录”。

在该体系中，AI 的角色是辅助阅读、归纳、检查和生成工程记录。AI 不替代人工做最终产品判断，不替代测试执行，不替代代码事实，不自动完成全部项目，也不自动承诺未来功能已经实现。

## 4. 人工如何约束 AI

本轮人工约束体现在以下方面：

1. 明确限定读取范围：只读取当前主仓库内指定治理文档和 ADR。
2. 明确限定修改范围：只生成或完善 `docs/10_代码Review记录.md`、`docs/11_AI协作记录.md`。
3. 明确禁止事项：不修改业务代码，不读取或修改 `software-practice-records`。
4. 明确内容口径：必须体现半自动工程化开发体系，必须体现当前分支是工程治理分支。
5. 明确风险口径：不夸大 AI 作用，不写成 AI 自动完成全部项目。
6. 明确事实口径：没有运行验证的内容只能写成“需人工确认”。

这些约束使 AI 的输出被限制在“辅助整理工程证据”的范围内，而不是越权进入业务实现、架构重写或外部资料迁移。

## 5. Git commit 如何保存证据

当前半自动工程体系要求通过 Git 小步提交保存证据。建议每一轮协作结束后按以下方式保留证据：

```bash
git status --short --branch
git diff -- docs/10_代码Review记录.md docs/11_AI协作记录.md
git add docs/10_代码Review记录.md docs/11_AI协作记录.md
git commit -m "docs: add review and AI collaboration records"
```

证据保存要点：

| 证据类型 | 建议保存方式 |
|---|---|
| 分支定位 | `git status --short --branch` 显示当前位于 `process/unified-main-repo`。 |
| 修改范围 | `git diff -- docs/10_代码Review记录.md docs/11_AI协作记录.md` 确认只改工程记录。 |
| 记录正文 | 通过 Git commit 保存 Review 记录和 AI 协作记录。 |
| 人工确认 | 提交前由人工确认是否接受文档口径和待确认事项。 |
| 后续测试 | 测试执行后另行提交测试报告，不与本轮记录混合。 |

注意：Git commit 只能保存“本轮文档变更证据”，不能替代测试通过、AI 真实调用通过或人工最终验收。

## 7. 本轮没有让 AI 做的事情

1. 未让 AI 修改业务代码。
2. 未让 AI 重构模型、路由、模板、CSS 或 JS。
3. 未让 AI 更换技术栈。
4. 未让 AI 读取、同步、迁移或覆盖 `software-practice-records`。
5. 未让 AI 伪造测试结果。
6. 未让 AI 声称真实 AI API 调用已经通过。
7. 未让 AI 自动决定 v0.6、v0.7 或 v1.0 的下一实现版本。

## 8. 后续协作建议

后续继续按半自动工程体系推进：

1. 每轮开始先明确需求、范围、禁止事项和验收证据。
2. AI 可辅助生成需求、设计、Review、测试计划和文档，但输出必须经代码事实和人工确认。
3. 代码变更前先确认需求和设计；架构或数据库变化前先补 ADR。
4. 修改完成后先看 `git diff`，确认没有业务代码误改或无关重构。
5. 用 Git 小步提交保存每个阶段证据，不把测试、重构、文档和临时实验混成一个提交。
6. 测试记录必须来自实际执行，未执行时写明未执行原因。
7. AI 协作记录应记录关键约束、关键输出和人工确认，不保存未经校验的长篇 AI 原始回答作为事实。
