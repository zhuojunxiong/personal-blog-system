# 教师 Agent 与 Skill 融入说明

生成日期：2026-07-01

当前分支：`work/v1.0-course-delivery`

本文用于说明教师提供的 Agent、Skill 与 Vibe Coding 工作流如何融入本项目 v1.0 课程交付流程。本文只创建项目说明文档，不修改业务代码，不读取或修改 `software-practice-records`，不复制教师资料全文，不复制 zip，不提交 jar、字体、缓存、HTML 或无关二进制资源。

## 1. 融入背景

`personal-blog-system` 已从早期“需求驱动快速原型”进入“课程交付与工程治理”阶段。当前项目不仅需要系统可运行、可演示，也需要能说明需求、设计、实现、测试、Review、AI 协作和人工确认之间的关系。

教师提供的 Agent、Skill 和 Vibe Coding 工作流资料，适合作为课程实践方法参考。本项目的融入目标不是把教师资料整体搬进仓库，也不是借此扩大业务范围，而是把其中的角色分工、文档生成、质量检查和协作流程转化为本项目可展示、可追溯、可答辩的工程证据。

## 2. 融入原则

| 原则 | 本项目执行方式 |
| --- | --- |
| 事实优先 | 以当前代码和 `docs/` 正式文档为事实源，教师资料只作为方法参考。 |
| 不夸大使用程度 | 已实际用于本轮的写成“已使用”；未运行、未产出、未验证的写成“计划使用/可用于”。 |
| 文档先行 | Agent 与 Skill 先进入说明、映射、CR、ADR、测试和 Review 流程，不直接触发业务代码修改。 |
| 人工确认 | 需求范围、技术路线、测试结论、答辩材料口径均需要人工确认。 |
| 最小纳入 | 只吸收适合本项目交付的流程和模板，不提交无关资源。 |
| 保持技术路线 | 继续遵守 ADR-002：保留 Flask + Jinja2 + SQLAlchemy + SQLite，不因教师资料更换技术栈。 |

## 3. 为什么不直接复制全部教师资料

不直接复制全部教师资料，主要基于以下原因：

1. 教师资料是课程方法参考，不等同于本项目事实源。
2. 原始资料中可能包含 zip、jar、字体、缓存、HTML、示例工程或无关二进制资源，直接复制会污染仓库。
3. 全量搬运会模糊“教师资料”和“本项目原创交付物”的边界，不利于答辩说明。
4. 本项目需要的是项目化吸收后的流程、映射和证据，而不是原始资料堆放。
5. 未实际运行的 Skill 或工具不能写成已经完成产出，否则会造成测试、文档导出或 UML 渲染结果被夸大。

因此，本项目采用“参考资料目录可查阅、正式仓库只保留项目化说明和必要骨架”的方式。

## 6. Vibe Coding 工作流与本项目流程的映射

| Vibe Coding 工作流环节 | 本项目 Git / CR / ADR / 测试 / Review 流程映射 |
| --- | --- |
| 需求输入与澄清 | 先建立 CR，说明背景、范围、不纳入范围、人工确认事项和验收口径。 |
| 设计与方案判断 | 涉及架构、数据库、技术栈或工具链变化时，先补 ADR 或 ADR 判断。 |
| 小步实现 | 代码变更必须对应明确需求；本轮只创建文档，不进入业务代码实现。 |
| Git 保存证据 | 每轮通过 `git status`、`git diff` 和小步提交保存变更范围。 |
| 测试验证 | 测试报告只能记录实际执行结果；未执行写“待执行/未执行”，不能写成通过。 |
| Review 复盘 | 通过 Review 记录风险、缺陷、是否需要重构和后续人工确认事项。 |
| AI 协作记录 | 在 `docs/11_AI协作记录.md` 或后续记录中保存输入范围、输出边界、未执行项和人工约束。 |

概括来说，Vibe Coding 工作流在本项目中对应“从需求、设计、实现、测试到复盘的 AI 协作开发流程”。它用于约束协作节奏和证据保存方式，不替代代码事实、测试结果或人工确认。

## 9. 不纳入本项目仓库的资源类型

以下资源不纳入当前项目仓库，除非后续有明确 CR、必要性说明和人工确认：

| 资源类型 | 不纳入原因 |
| --- | --- |
| 原始 zip 包 | 体积大、不可直接追溯、容易包含无关内容。 |
| 教师资料全文 | 教师资料是课程参考，不应整体复制为项目文档。 |
| jar 文件 | 工具依赖不应随意提交；例如 PlantUML 渲染应优先记录环境或使用外部安装。 |
| 字体文件 | 容易引入版权和体积问题，当前文档说明不需要。 |
| 缓存目录 | 不属于可维护交付物。 |
| HTML 导出物 | 若非最终交付要求，容易与源文档重复。 |
| 无关二进制资源 | 与项目事实、代码、测试和答辩证据无直接关系。 |
| `software-practice-records` 内容 | 当前不作为事实源，本轮明确不读取、不修改、不迁移。 |

## 10. 对课程答辩的价值

教师 Agent 与 Skill 融入说明可以帮助答辩时回答以下问题：

1. 本项目如何使用 AI 辅助需求、设计、测试和 Review。
2. 哪些能力已经实际用于当前交付，哪些只是后续计划。
3. 为什么没有简单搬运教师资料，而是转化为项目化流程。
4. Git、CR、ADR、测试报告、Review 记录和 AI 协作记录如何形成证据链。
5. AI 输出如何接受人工确认、代码事实和测试结果约束。

## 12. 对软件工程过程的价值

本说明强化了以下软件工程过程：

1. 需求变更通过 CR 进入，不绕过范围确认。
2. 架构与技术路线变化通过 ADR 判断，不直接改栈或重写。
3. 数据库、前端、测试、Review 各有角色边界，减少 AI 越权。
4. 测试结果必须来自真实执行，未执行事项保持可见。
5. 文档导出、UML、视觉验收等能力先记录条件和边界，再实际执行。
6. Git 小步提交用于保存证据，避免把文档、测试、代码和实验混在一起。
