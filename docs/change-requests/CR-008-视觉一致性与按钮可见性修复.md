# CR-008 视觉一致性与按钮可见性修复

## 0. 使用说明

本文用于记录 `work/v1.0-course-delivery` 分支下视觉一致性与按钮可见性问题的后续修复请求。

本文只创建视觉修复 CR，不修改业务代码，不代表已经进入实现。后续如进入实现，只允许在本 CR 约束范围内修改模板和样式相关文件，并需要在修复后重新进行截图验收。

本文不读取或修改 `software-practice-records`。本文继续遵守 ADR-002 方案 B：保留 Flask + Jinja2 + SQLAlchemy + SQLite，不更换技术栈，不进行前后端分离，不引入无关重构。

## 3. 变更背景

CR-004 启动和功能验证已完成，核心功能可运行，E2E 通过，但浏览器人工验收发现多处 UI 问题。

CR-004 的结论表明：

1. 项目可以启动并访问主要页面。
2. 初始化、演示数据、管理员登录、普通用户登录、后台访问和 E2E 测试已经完成验证。
3. 相关页面数据仍能显示，核心功能链路可运行。
4. 公开列表页、注册页、后台登录页、后台管理页和我的专栏页存在视觉一致性、按钮文字可见性或布局混乱问题。

本 CR 的目标是把这些视觉问题独立收束为一次受控的视觉修复请求，避免在 CR-004 中直接修改代码，也避免将视觉修复扩大为业务逻辑、数据库结构或技术栈调整。

## 6. 修复范围

### 允许修改

1. 模板文件，例如 `app/templates/` 下与上述页面直接相关的 Jinja2 模板。
2. 样式文件，例如 `app/static/` 下与页面布局、颜色、按钮、表格、卡片、表单和响应式表现相关的 CSS 文件。
3. 少量仅服务视觉交互的模板内 class、结构和样式引用调整。

### 不允许修改

1. 不修改业务逻辑。
2. 不修改数据库结构。
3. 不新增功能。
4. 不更换技术栈。
5. 不新增后端路由、Service、模型或数据库迁移。
6. 不改变现有权限规则、登录流程、文章/专栏/评论等业务数据规则。
7. 不读取或修改 `software-practice-records`。

## 7. 设计约束

1. 继续遵守 ADR-002 方案 B，保留 Flask + Jinja2 + SQLAlchemy + SQLite。
2. 视觉修复应以当前 v1.0 前台风格为基准，优先统一布局、按钮、卡片、表格、表单、间距和颜色。
3. 修复公开列表页时，应保证文章、分类、标签、专栏等数据仍按当前页面逻辑显示。
4. 修复后台页面时，应保证统计数据、列表数据、操作入口和权限提示仍能显示。
5. 修复 `/register` 和 `/admin/login` 时，应优先解决按钮默认态文字清晰可见问题，不改变登录或注册业务流程。
6. 修复 `/my/columns` 时，应保留已有专栏数据展示和创建专栏入口，不新增专栏业务能力。

| 验收编号 | 验收项 | 通过标准 |

| AC-004 | 页面风格统一 | 相关页面与 v1.0 前台风格在颜色、间距、按钮、卡片、表格和表单观感上保持一致 |
| AC-005 | 后台页面观感改善 | 后台仪表盘、用户管理、文章管理、评论管理和 AI 状态页不再呈现明显旧版风格割裂 |

| AC-007 | 修复后重新截图验收 | 对涉及页面重新截图，保存或记录截图验收结论 |
| AC-008 | 不引入范围外变化 | 不修改业务逻辑、数据库结构、技术栈或新增功能 |

## 9. 后续测试方式

后续实现完成后，应至少执行以下测试和验收：

1. 启动本地服务，确认 `http://127.0.0.1:5000/` 可访问。
2. 使用浏览器人工访问以下前台页面并截图：
   - `/discover`
   - `/articles`
   - `/categories`
   - `/tags`
   - `/columns`
   - `/register`
3. 使用管理员账号访问以下后台页面并截图：
   - `/admin/login`
   - `/admin/dashboard`
   - `/admin/users`
   - `/admin/articles/`
   - `/admin/comments`
   - `/admin/ai`
4. 使用普通用户账号访问并截图：
   - `/my/columns`
5. 检查按钮默认态：
   - `/register` 注册按钮未悬停状态文字清晰可见。
   - `/admin/login` 登录按钮未悬停状态文字清晰可见。
6. 检查数据展示：
   - 前台列表页仍能显示演示文章、分类、标签和专栏数据。
   - 后台页面仍能显示统计、用户、文章、评论和 AI 状态信息。
   - `/my/columns` 仍能显示当前用户专栏数据和创建入口。
7. 执行现有 E2E 或回归测试，确认视觉修复未破坏登录、注册、文章访问、后台访问和个人中心相关主流程。
8. 记录截图验收结果、测试命令、通过/失败数量和发现的问题；不得把未执行项目写成通过。
