# CR-009 AI 驱动知识写作与搜索平台重基线

## 1. 变更背景

当前项目已经具备多用户写作、搜索、评论、点赞、收藏、专栏和后台治理能力，但产品主线容易被分类、标签、专栏等传统博客结构分散。

本次变更将项目重新收束为“AI 驱动的知识写作与搜索平台”：让知识从被写出来，到被 AI 总结，再到被读者用自然语言准确找到，形成完整闭环。

## 2. 变更目标

1. 首页以极简 AI 搜索为主入口。
2. `/` 仅作为首次进入页，进入后回到 `/home`。
3. `/home` 作为后续前台首页和主要搜索入口。
4. 写作页以 Markdown 写作为核心，AI 助手保留资料搜索、大纲、润色和搜索摘要能力。
5. 文章发布时生成搜索用 AI 摘要，摘要进入搜索召回范围。
6. 用户公开主页支持 Markdown 个性化展示。
7. 分类、标签和专栏不删除，但前台弱化；专栏定位调整为作者知识合集。

## 3. 范围

本次纳入：

- 首页、搜索页、写作页、作者主页的产品文案和界面重心调整。
- `Article` 增加 AI 搜索摘要相关字段。
- `User` 增加 Markdown 个人主页字段。
- AI 服务增加搜索摘要和资料搜索能力。
- 文章发布时自动刷新搜索摘要；AI 不可用时使用本地降级摘要。
- 传统搜索和 AI 搜索纳入 AI 搜索摘要字段。
- README、需求、概要设计、ADR 和 AI 协作记录同步口径。

本次不纳入：

- 向量数据库。
- 前后端分离。
- 技术栈替换。
- 复杂推荐算法。
- 多模型供应商切换。
- 流式 AI 输出。

## 4. 需求说明

### 4.1 自然语言搜索

用户在 `/home` 输入自然语言问题。系统优先通过 AI 理解搜索意图并匹配文章；AI 不可用时回退到关键词搜索。

搜索结果应强调：

- 推荐理由。
- 文章解决的问题。
- AI 搜索摘要。
- 作者和互动数据。

### 4.2 写作工作台

写作页保留左右分栏：

- 左侧：标题、摘要、Markdown 正文和发布设置。
- 右侧：AI 助手。

AI 助手能力收束为：

1. 搜资料。
2. 生成大纲。
3. 润色正文。
4. 生成搜索摘要。

标签推荐、标题建议和文章问答不作为当前主按钮强调。

### 4.3 发布后 AI 搜索摘要

文章发布时，系统自动生成搜索用摘要。AI 配置可用时调用 AI；AI 不可用或调用失败时，使用标题、人工摘要和正文前段生成降级摘要。

搜索摘要用于提升后续自然语言搜索命中率，不等同于普通页面摘要。

### 4.4 Markdown 个人主页

用户可维护 Markdown 个人主页内容，用于展示作者简介、研究方向、代表文章、学习路线、项目经历和知识合集。

### 4.5 分类、标签、专栏

分类、标签和专栏保留为系统内部组织、后台治理和作者知识合集能力。

前台主导航和首页不再强调分类、标签和全站专栏。

## 5. 风险与回滚

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| 旧 SQLite 数据库缺少新增字段 | 页面访问或保存时报错 | 增加轻量字段补齐逻辑，并在初始化脚本同步字段。 |
| AI API 未配置 | 发布时无法真实生成 AI 摘要 | 使用本地降级摘要，不阻断发布。 |
| AI 资料搜索依赖外部网页可访问性 | 结果可能不稳定 | 失败时返回可读错误，并保留写作主流程。 |
| 首页入口变化影响旧链接 | 用户仍访问 `/` | `/` 保留首次进入页，其他导航统一指向 `/home`。 |

回滚方式：

1. 保留新增字段但不在页面展示。
2. 搜索服务移除 AI 搜索摘要字段召回。
3. 写作页恢复原 AI 按钮。
4. 首页导航恢复旧链接。

## 6. 测试要求

后续测试记录至少覆盖：

1. `/` 首次进入页可访问并进入 `/home`。
2. `/home` AI 搜索表单可提交；无 Key 时可降级。
3. 发布文章时无 AI Key 不阻断保存。
4. 搜索能匹配 `ai_search_summary`。
5. 用户资料页能保存和展示 Markdown 个人主页。
6. 点赞、收藏、评论不受影响。
