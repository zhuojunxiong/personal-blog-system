# 核心业务闭环分析

## 1. 文档状态

本文档用于 `v0.5.1-governance` 阶段的产品重新基线化，分析当前系统已经形成或尚未形成的核心业务闭环，并给出后续保留、推迟和重新设计建议。

依据范围：

1. `AGENTS.md`
2. `docs/product-rebaseline/01_项目定位再分析.md`
3. `docs/product-rebaseline/02_用户角色与使用场景.md`
4. `docs/02_v0.5.1需求追溯.md`

约束说明：

1. 本文只做业务闭环分析，不修改业务代码。
2. 本文不新增当前实现范围。
3. 本文不把未验证能力写成已完成。
4. 当前事实以 `docs/02_v0.5.1需求追溯.md` 中 F001-F050 的状态为主要依据。
5. 对 AI 相关能力统一区分“代码接口存在”“真实 API 调用需验证”“日志采纳闭环未完整成立”。

## 2. 闭环判断标准

本文将业务闭环分为三类：

| 状态 | 判断标准 | 文档表述要求 |
| --- | --- | --- |
| 已成立 | 起点、关键步骤、终点、权限或状态流转均已有当前代码或正式文档依据，且不依赖未确认的外部服务。 | 可写为当前主链路，但仍可标注测试、视觉或体验细节需补证据。 |
| 部分成立 | 主入口或核心接口存在，但存在关键断点，例如真实 API 调用未验收、前端入口不清晰、日志采纳未闭合、数据模型替代实现等。 | 只能写为部分支持、需验证或后续候选，不能写成完整业务闭环。 |
| 未成立或待重设计 | 当前只是计划、提示、模板或需求边界不清，无法形成稳定起点到终点。 | 应推迟、删除出当前基线，或先补需求和设计。 |

## 4. 游客浏览闭环

### 4.1 当前闭环

游客浏览闭环是当前系统最基础的内容消费链路：

1. 游客进入首页、旧首页/搜索入口页、发现页或公开文章列表。
2. 游客通过文章列表、分类、标签、专栏、作者主页或传统关键词搜索发现内容。
3. 游客进入已发布文章详情页阅读内容。
4. 系统记录阅读量并展示文章基础信息。
5. 游客如果需要评论、点赞、收藏或创作，则转入登录或注册流程。

### 4.2 成立程度

该闭环已经成立。

依据包括 F001-F007：公开页面访问、文章详情、分类浏览、标签浏览、公开专栏、作者主页和传统关键词搜索均标注为已实现。

### 4.3 断点与风险

1. 阅读量统计虽然有代码依据，但刷新、重复阅读和异常访问规则仍需测试确认。
2. 首页、旧首页、发现页、搜索入口页之间的产品命名和导航层级尚需统一。
3. AI 智能搜索不能并入游客浏览主闭环，因为 F032 仍属于接口存在且真实调用需验证。
4. V0.4 UI 视觉一致性仍需验收，不能作为当前已经完整完成的浏览体验结论。

### 4.4 取舍建议

优先保留。游客浏览闭环是系统展示、课程演示和后续所有互动、创作转化的入口，应作为 P0 主链路继续维护。

## 5. 用户注册登录闭环

### 5.1 当前闭环

用户注册登录闭环支撑游客向注册用户转化：

1. 游客打开注册页并提交账号信息。
2. 注册成功后自动登录。
3. 用户可通过用户名或邮箱登录，也可退出登录。
4. 登录用户可编辑个人资料、修改密码。
5. 登录态作为评论、点赞、收藏、创作和个人中心的前置条件。

### 5.2 成立程度

核心账号闭环已经成立。

依据包括 F008-F011：注册、登录、退出、资料编辑和密码修改均标注为已实现。F012 的个人中心、存档、阅读、交流相关页面为部分实现，因此不能把完整个人空间闭环写成已成立。

### 5.3 断点与风险

1. F012 中最近阅读当前用收藏替代，真实 ReadingHistory 未作为已实现需求。
2. 个人中心、存档、阅读、交流页面的产品边界仍需确认。
3. 普通登录和管理员登录入口在产品文案上是否需要区分，仍需确认。
4. README 中“修改密码”的历史表述与当前代码能力存在口径冲突，需后续文档同步。

### 5.4 取舍建议

优先保留账号闭环。个人中心扩展能力应保留但调整边界，尤其是真实最近阅读、交流页定位和个人空间信息架构需要先确认后再增强。

## 6. 内容创作闭环

### 6.1 当前闭环

内容创作闭环是注册用户从内容生产到公开发布的主链路：

1. 登录用户进入写作页或个人文章管理入口。
2. 用户填写标题、正文、摘要、分类、标签和专栏等信息。
3. 用户保存草稿或发布文章。
4. 作者可继续编辑或删除自己的文章。
5. 非作者不能编辑或删除他人文章。
6. 发布后的文章进入游客浏览闭环。

### 6.2 成立程度

该闭环已经成立。

依据包括 F014-F015：新建文章、保存草稿、发布文章、编辑和删除自己的文章均标注为已实现。F013 的专栏能力也为文章组织提供了支撑。

### 6.3 断点与风险

1. 发布后是否立即公开、是否需要管理员审核，目前需求未定义。
2. 草稿在前台是否可见、草稿状态的展示和权限边界仍需测试确认。
3. 所有注册用户是否默认具备创作权限，还是后续需要创作者准入机制，仍需人工确认。
4. AI 写作辅助不能作为内容创作闭环的前置条件，因为 AI 真实调用仍需验证。

### 6.4 取舍建议

优先保留。内容创作闭环是多用户知识专栏博客系统的核心生产链路，应保持稳定，不建议在 v0.5.1-governance 阶段引入创作者等级、审核团队、收益分成等大型平台能力。

## 7. 专栏组织闭环

### 7.1 当前闭环

专栏组织闭环用于把单篇文章组织成专题内容：

1. 登录用户创建自己的专栏。
2. 用户编辑或删除自己的专栏。
3. 用户在写作或编辑文章时选择专栏。
4. 游客在前台浏览专栏列表和专栏详情。
5. 管理员可在后台启用或禁用专栏。

### 7.2 成立程度

该闭环主体已经成立。

依据包括 F005、F013、F025：公开专栏列表和详情、用户创建编辑删除自己的专栏、管理员启用禁用专栏均标注为已实现。

### 7.3 断点与风险

1. 专栏是否必须作为文章发布前置条件，当前仍需确认。
2. 删除专栏时关联文章如何处理，需测试和产品规则确认。
3. 禁用专栏后，专栏详情、关联文章和文章详情页中的专栏信息如何展示，仍需确认。
4. 管理员后台治理与作者自主管理之间的边界文案需统一。

### 7.4 取舍建议

优先保留，但需要补充关联规则。专栏是当前项目区别于普通博客的重要组织能力，应保留为 P1 以上能力；删除、禁用和文章关联规则可以在后续设计文档中补齐。

## 8. 评论互动闭环

### 8.1 当前闭环

评论互动闭环支撑读者对内容进行轻量反馈：

1. 登录用户在文章详情页提交评论。
2. 评论默认进入待审核状态。
3. 管理员审核通过、隐藏或删除评论。
4. 通过审核的评论进入文章详情展示链路。
5. 登录用户可点赞或取消点赞文章。
6. 登录用户可收藏或取消收藏文章。
7. 数据库唯一约束避免同一用户重复点赞或收藏同一文章。

### 8.2 成立程度

该闭环已经成立，但互动体验细节仍需验收。

依据包括 F017-F020 和 F018：评论提交、评论审核、点赞、收藏均标注为已实现。

### 8.3 断点与风险

1. 评论审核前本人是否可见、游客是否完全不可见，仍需产品确认和测试验证。
2. 点赞数、收藏状态刷新、重复提交和异常返回体验需测试确认。
3. 收藏当前被个人中心最近阅读替代使用，容易造成产品语义混淆。
4. 评论互动与通知、关注、私信等大型社区能力没有当前实现依据，不应扩展进当前闭环。

### 8.4 取舍建议

优先保留。评论、点赞、收藏是当前系统轻互动能力的基本闭环，应继续维持简洁边界，不建议短期扩展为完整社区关系链。

## 9. 管理后台治理闭环

### 9.1 当前闭环

管理后台治理闭环用于保障内容、用户和基础配置可被管理员维护：

1. 管理员通过管理员登录入口进入后台。
2. 后台权限由管理员角色限制，普通用户不能访问。
3. 管理员查看仪表盘统计。
4. 管理员管理用户状态、全站文章、评论、分类、标签和专栏。
5. 管理员查看 AI 接口配置状态。
6. 前台内容展示和用户状态受到后台治理结果影响。

### 9.2 成立程度

该闭环已经成立。

依据包括 F016、F018、F021-F025、F034 和 F042：后台仪表盘、用户管理、文章管理、评论管理、分类管理、标签管理、专栏启用禁用、AI 配置状态和后台权限限制均有当前依据。

### 9.3 断点与风险

1. 后台治理说明仍需增强，尤其是演示路径、权限边界和管理范围。
2. 用户禁用后登录、前台展示和历史内容状态的具体效果需确认。
3. 分类、标签、专栏删除或禁用后的关联内容处理规则需确认。
4. AI 状态页只代表配置状态，不等同于真实 API 调用成功。
5. AI 日志治理闭环未完整成立，不能写成管理员已可完整审计 AI 采纳和问题反馈。

### 9.4 取舍建议

优先保留。后台治理闭环是课程交付和多用户系统可信运行的基础。后续可增强说明和测试证据，但不建议扩展为复杂运营平台。

## 10. AI 辅助写作闭环

### 10.1 当前闭环

AI 辅助写作闭环的理想路径是：

1. 创作者在写作页输入文章内容或写作上下文。
2. 创作者请求摘要生成、标签推荐、正文润色、文章问答、大纲提取或标题建议。
3. 系统调用 OpenAI 兼容接口。
4. AI 返回建议内容，前端展示给创作者。
5. 创作者选择是否采纳建议。
6. 系统记录调用日志、采纳结果或问题反馈。

### 10.2 成立程度

该闭环只是部分成立。

依据包括 F026-F031、F033、F045-F046：写作页 AI 接口存在，未配置 Key 和异常场景有友好处理，基础日志写入能力存在。但真实 API 调用未在当前追溯中验证，采纳结果、是否采纳、问题标记等字段暂未形成完整写入流程。

### 10.3 断点与风险

1. API Key、远程调用、超时、返回格式和失败场景仍需真实验收。
2. AI 输出是自动填充、插入建议还是由用户手动复制采纳，规则需确认。
3. 标签推荐是否自动创建标签，还是只能从已有标签中选择，规则需确认。
4. AiLog 基础字段存在，但采纳、问题标记和管理员侧查看未形成完整闭环。
5. AI 写作能力如果被写成创作主流程前置条件，会增加不稳定外部依赖风险。

### 10.4 取舍建议

保留为辅助能力，但不要上升为创作主闭环。下一步应优先做真实调用验收和日志采纳需求确认，再决定是否增强交互。大纲和标题建议可低于摘要、标签、润色等核心辅助能力。

## 11. AI 搜索闭环

### 11.1 当前闭环

AI 搜索闭环的理想路径是：

1. 用户在搜索入口输入自然语言查询。
2. 系统进行意图理解和关键词扩展。
3. 系统使用 SQL 候选检索获得候选文章、专栏或用户结果。
4. 系统调用 AI 进行重排序并生成理由。
5. AI 调用失败时回退到传统搜索或候选结果。
6. 用户获得可解释的搜索结果。

### 11.2 成立程度

该闭环只是部分成立。

依据包括 F032：AI 智能搜索接口和前端入口存在，但真实 API 调用、失败 fallback、无 Key 场景、不同用户角色入口一致性和结果体验仍需确认。传统关键词搜索 F007 已成立，但不能替代 AI 搜索闭环的验收。

### 11.3 断点与风险

1. AI 搜索依赖外部模型调用，真实成功率和响应时间需验证。
2. 无 Key、远程失败、超时和格式异常时的降级体验需测试确认。
3. AI 搜索入口面向游客、注册用户或管理员是否一致开放，仍需产品确认。
4. 传统搜索已经成立，AI 搜索若直接替代传统搜索，会带来可用性风险。
5. 当前无向量检索、多轮搜索、复杂推荐排序等明确必做需求，不应默认扩展。

### 11.4 取舍建议

推迟为搜索增强候选。传统搜索应继续作为稳定主入口，AI 搜索可在真实调用验收、降级策略和结果展示明确后再提升优先级。

## 18. 结论

当前 v0.5.1 的稳定业务主干已经形成，主要包括：

1. 游客浏览。
2. 用户注册登录。
3. 内容创作。
4. 专栏组织。
5. 评论互动。
6. 管理后台治理。

其中游客浏览、注册登录、内容创作和管理后台治理应作为下一阶段最优先保留的 P0 闭环。专栏组织和评论互动也应保留，但需要补充关联规则、审核可见性和体验验收。

AI 辅助写作和 AI 搜索不宜写成完整主闭环。它们当前更适合定位为辅助增强能力：AI 写作可优先保留摘要、标签、润色等与创作强相关的能力，并先完成真实 API 调用验收；AI 搜索应推迟为传统搜索之上的增强层，确认降级策略后再提高优先级。

最需要重新设计或补充规则的部分是个人中心与真实阅读记录、AI 输出采纳日志、AI 搜索入口与降级体验、专栏关联规则、评论状态可见性，以及后台 AI 治理边界。
