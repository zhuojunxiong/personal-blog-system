# 功能清单与取舍矩阵

## 1. 文档状态

本文档用于 `v0.5.1-governance` 阶段的产品重新基线化，基于当前 F001-F050 需求清单，对功能进行保留、完善、推迟、删除或暂不纳入的取舍判断。

依据范围：

1. `AGENTS.md`
2. `docs/product-rebaseline/01_项目定位再分析.md`
3. `docs/product-rebaseline/02_用户角色与使用场景.md`
4. `docs/product-rebaseline/03_核心业务闭环分析.md`
5. `docs/02_v0.5.1需求追溯.md`

约束说明：

1. 本文只做功能清单和取舍分析，不修改业务代码。
2. 本文不把未验证、部分实现或后续计划写成已完成。
3. 只有经过人工确认并同步进入正式需求、设计、CR 或 ADR 的内容，才能作为后续实现依据。
4. 本文中的 CR 指正式变更请求或变更记录；ADR 指架构决策记录。
5. “是否需要测试保护”表示若后续修改该功能，应补充或执行对应测试保护；不表示本次已经完成测试。

## 2. 取舍规则

| 分类 | 判断标准 | 后续处理原则 |
| --- | --- | --- |
| 保留 | 当前已实现，属于游客浏览、账号、创作、互动、后台治理、安全或工程基础主链路。 | 纳入当前产品基线；后续以测试、文档和演示证据补强为主。 |
| 完善 | 当前已实现或部分实现，但存在规则不清、验证不足、文档口径冲突、体验细节或治理证据缺口。 | 不直接重写；先补确认、测试和设计说明，必要时通过 CR 小步增强。 |
| 推迟 | 代码接口存在或有计划价值，但依赖外部服务、真实调用、产品入口或闭环规则尚未确认。 | 不作为当前主链路；先验收和补需求，确认后再进入后续版本。 |
| 删除/暂不纳入 | 当前只是后续提示、无完整接口或会扩大项目边界，不适合作为当前基线功能。 | 不纳入当前验收和近期实现范围；如课程或产品要求变化，需重新立项。 |
