# 竞品参考与边界说明

## 1. 文档状态

本文档用于 `v0.5.1-governance` 阶段的产品重新基线化，说明本项目在产品分析时可以参考的产品类型、可借鉴能力和明确不照搬范围。

依据范围：

1. `AGENTS.md`
2. `docs/product-rebaseline/01_项目定位再分析.md`
3. `docs/product-rebaseline/02_用户角色与使用场景.md`
4. `docs/product-rebaseline/03_核心业务闭环分析.md`
5. `docs/product-rebaseline/04_功能清单与取舍矩阵.md`
6. `docs/02_v0.5.1需求追溯.md`

约束说明：

1. 本文只做竞品参考和产品边界说明，不修改业务代码。
2. 本文不写实时市场事实，不描述具体商业产品的最新功能。
3. 本文只参考产品类型和通用能力，不把任何参考对象写成必须照搬。
4. 本文不引入外部系统能力作为当前已确认需求。
5. 只有经过人工确认，并同步进入正式需求、产品设计、软件设计、CR 或 ADR 的内容，才能作为后续实现依据。

## 2. 参考原则

| 原则 | 说明 |
| --- | --- |
| 参考产品类型，不照搬商业产品 | 本项目可参考个人博客、多人知识社区、专栏写作平台、AI 辅助写作工具、课程实践类管理系统的通用设计思路，但不对标某一个商业产品。 |
| 以当前项目定位为边界 | 当前定位以课程实践系统和多用户知识专栏博客系统为主，优先服务公开浏览、账号、创作、互动、后台治理、安全和文档追溯。 |
| 以课程验收优先于商业化复杂度 | 课程验收更关注功能闭环、权限边界、代码结构、测试证据、文档追溯和可复现启动，不优先追求商业化增长能力。 |
| 不把亮点能力变成主链路依赖 | AI 写作和 AI 搜索可以作为辅助亮点候选，但在真实调用、降级和采纳规则未确认前，不应替代传统搜索或内容创作主链路。 |
| 参考必须可追溯 | 任何从参考对象转化而来的需求、设计或软件结构变化，都应能映射到 F001-F050、CR、ADR、测试或人工确认事项。 |

## 4. 分类参考分析

### 4.1 个人博客系统

| 分析项 | 内容 |
| --- | --- |
| 可借鉴部分 | 首页和文章列表作为游客入口；文章详情作为阅读核心；分类、标签、作者主页和归档用于内容发现；传统关键词搜索作为稳定查找入口。 |
| 不应照搬部分 | 不应退回单作者模型；不应忽略普通用户、内容创作者和管理员的权限边界；不应把系统简化为静态内容展示。 |
| 影响需求 | 影响 F001-F007、F010、F012，支撑公开浏览、搜索、作者展示和个人空间边界。 |
| 影响产品设计 | 影响首页、发现页、文章详情、分类标签页、作者主页和空状态设计。 |
| 影响软件设计 | 影响 public 路由、ArticleService 查询、分类标签模型、作者文章关联和搜索查询结构。 |
| CR/ADR/测试保护 | 现有主链路保留通常不需要 CR；若调整首页命名、搜索结果排序或新增 ReadingHistory，需要 CR；新增模型可能需要 ADR；相关页面需测试保护。 |
| 人工确认事项 | 首页、旧首页、发现页和搜索入口页命名是否统一；真实最近阅读是否从收藏中拆分。 |

### 4.2 多人知识社区

| 分析项 | 内容 |
| --- | --- |
| 可借鉴部分 | 多用户内容生产、评论审核、点赞收藏、用户状态管理、后台治理和基础权限隔离。 |
| 不应照搬部分 | 不引入关注、私信、热榜、复杂推荐算法、用户等级、内容运营活动、商业社区风控体系和大规模社区增长机制。 |
| 影响需求 | 影响 F008-F020、F021-F025、F041-F043，支撑账号、互动、评论治理、用户状态和后台权限。 |
| 影响产品设计 | 影响登录注册、个人中心、文章互动区、评论状态提示、后台用户和评论管理页面。 |
| 影响软件设计 | 影响 Flask-Login 权限、admin_required、Comment/Like/Favorite 唯一约束、用户状态控制和后台 Blueprint。 |
| CR/ADR/测试保护 | 轻互动和治理规则调整需要 CR；若新增关注、通知、私信或推荐模型，应先 ADR，但当前不建议纳入；权限和互动必须测试保护。 |
| 人工确认事项 | 所有注册用户是否默认可创作；评论审核前后可见性；禁用用户后的登录、展示和历史内容状态。 |

### 4.3 专栏写作平台

| 分析项 | 内容 |
| --- | --- |
| 可借鉴部分 | 专栏作为专题组织单元；专栏列表和详情支撑内容聚合；作者主页展示文章和专栏；写作时选择专栏增强内容结构。 |
| 不应照搬部分 | 不引入付费专栏、会员订阅、收益分成、签约作者、机构号、商业推荐位或复杂分发规则。 |
| 影响需求 | 影响 F005、F006、F013-F016、F021、F025，支撑专栏展示、创作者管理和后台治理。 |
| 影响产品设计 | 影响专栏列表、专栏详情、写作页专栏选择、作者主页和后台专栏状态提示。 |
| 影响软件设计 | 影响 BlogColumn 模型、文章与专栏关联、专栏启用禁用规则、作者权限校验和后台专栏管理。 |
| CR/ADR/测试保护 | 专栏基础能力保留不需要 CR；若修改删除、禁用或文章关联规则，需要 CR；涉及数据模型变化时可能需要 ADR；专栏前后台展示需测试保护。 |

### 4.4 AI 辅助写作工具

| 分析项 | 内容 |
| --- | --- |

| 影响需求 | 影响 F026-F034、F045-F046；其中 F026-F032 仍需真实 API 调用确认，F033 仍需采纳和问题标记闭环确认。 |
| 影响产品设计 | 影响写作页 AI 按钮、结果展示、采纳方式、错误提示、AI 搜索入口和管理员 AI 状态页。 |
| 影响软件设计 | 影响 AIService、AI 路由、AiLog 模型、环境变量配置、超时和异常封装、AI JSON 接口 CSRF 豁免说明。 |
| CR/ADR/测试保护 | AI 真实增强、采纳闭环、AI 搜索开放范围均需要 CR；AI 搜索策略、日志闭环或新增字段可能需要 ADR；无 Key、超时、异常和降级必须测试保护。 |
| 人工确认事项 | AI 写作哪些能力进入下一版本必验；AI 输出如何采纳；推荐标签是否自动创建；AI 搜索是否开放给游客；AI 日志是否需要管理员查看和统计。 |

## 5. 明确不对标范围

本项目不是大型商业社区，也不追求大型内容平台的商业化复杂度。以下能力不作为当前基线和近期默认实现范围：

| 范围 | 当前取舍 | 原因 |
| --- | --- | --- |
| 复杂推荐算法 | 不纳入 | 当前传统搜索和基础内容组织已能支撑课程演示；复杂推荐会显著扩大算法、数据和测试范围。 |
| 热榜和流量分发 | 不纳入 | 当前无运营目标和实时热度数据依据，不适合作为课程实践主链路。 |
| 广告系统 | 不纳入 | 与课程验收和知识专栏博客主流程无直接关系，会引入商业运营复杂度。 |
| 支付和会员体系 | 不纳入 | 当前无付费内容、订单、退款、会员权益和财务安全需求。 |
| 关注、私信和完整关系链 | 不纳入 | 当前只保留评论、点赞、收藏等轻互动，避免演变为大型社区。 |
| 签约作者和收益分成 | 不纳入 | 当前创作者是注册用户的一种使用身份，不建立商业作者生态。 |
| 多 Provider、流式输出、向量检索 | 暂不纳入 | AI 基础调用和日志闭环仍需确认，不应提前扩大 AI 架构复杂度。 |
| 教务平台能力 | 不纳入 | 本项目可参考课程验收方法，但不是教务系统，不处理班级、成绩、考试和作业批改。 |

## 9. 结论

本项目可以参考的是产品类型，而不是照搬某个商业产品。当前最适合的参考组合是：

1. 用个人博客系统参考公开内容展示和基础搜索。
2. 用多人知识社区参考轻互动、权限和基础治理。
3. 用专栏写作平台参考知识专题组织。
4. 用 AI 辅助写作工具参考创作辅助和异常降级。
5. 用课程实践类管理系统参考交付证据、测试保护和文档追溯。

这些参考只能服务于当前产品定位：面向课程实践的多用户知识专栏博客系统。课程验收、稳定主链路、权限安全、测试证据和文档追溯优先级高于商业化复杂度。复杂推荐算法、商业化运营、广告、支付、会员体系、完整关系链和大型社区增长能力不属于当前基线。
