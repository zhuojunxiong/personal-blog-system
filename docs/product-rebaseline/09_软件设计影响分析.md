3. 本文保持 ADR-002 方案 B 口径：保留当前 Flask + Jinja2 + SQLAlchemy + SQLite 技术栈，在测试保护、需求确认和 ADR 约束下做受控局部重构。

5. 本文不读取、不引用、不同步 `software-practice-records`。

## 2. 当前架构基线

当前系统是服务端渲染的 Flask 单体应用，不是微服务，也不是前后端分离架构。自然形成的架构边界是：

| 层面 | 当前设计 | 说明 |
| --- | --- | --- |
| 应用组织 | Flask 工厂函数 + Blueprint | 由 `create_app()` 初始化扩展、注册蓝图和错误处理。 |
| 控制层 | 各业务 `routes.py` | 接收请求、做权限校验、调用 service 或 ORM、返回模板或 JSON。 |
| 业务层 | 各业务 `services.py` 和 `app/services.py` | 承载文章、分类、标签、专栏、评论、AI、用户等复用逻辑。 |
| 数据层 | SQLAlchemy + SQLite | `app/models.py` 集中定义用户、文章、专栏、分类、标签、评论、点赞、收藏和 AI 日志模型。 |
| 展示层 | Jinja2 模板 | 前台、个人中心、后台和错误页均采用服务端模板渲染。 |
| 静态资源 | `main.css`、`v041.css`、`v041.js` | 承载全局样式、v041 页面样式和少量前端交互。 |
| AI 适配 | `AIService` + OpenAI 兼容 Chat Completions API | 写作辅助和 AI 搜索接口存在，真实远程调用仍需配置 Key 后验证。 |

设计结论：

1. F001-F025、F038-F047 已由当前架构支撑主业务闭环和工程基础。
2. F026-F032 的 AI 能力应区分“接口存在”和“真实调用已验收”，不能直接作为稳定主链路前置条件。
3. F033 AI 日志已有模型和基础记录，但采纳、问题标记和后台查看闭环仍需确认。
4. F036-F050 多数属于启动、测试、视觉、文档和治理证据问题，不要求立即改动业务架构。

## 3. 保留类功能对当前架构的影响

保留类功能包括 F001-F010、F013-F019、F021-F024、F034、F038-F047。这些功能构成当前产品基线，不建议通过大范围重构重新证明。

| 功能范围 | 当前承载模块 | 对架构的影响 | 设计处理建议 |
| --- | --- | --- | --- |
| 游客浏览、文章阅读、分类标签、专栏、作者主页、传统搜索 | `public`、`ArticleService`、`CategoryService`、`TagService`、`ColumnService`、前台模板 | 稳定支撑公开内容消费链路；传统搜索是 AI 搜索之外的稳定主入口。 | 保留当前路由和模板体系；后续只在测试保护下做搜索体验或查询收敛。 |
| 注册、登录、退出、资料维护 | `auth`、`user`、`AuthService`、`UserService`、Flask-Login | 支撑账号和登录态边界；管理员登录与普通登录入口需要文案和测试口径统一。 | 不调整认证技术栈；补登录、注册、退出、禁用状态等回归测试。 |
| 专栏创建、文章创作、草稿发布、作者编辑删除 | `user`、`column`、`article`、`ArticleService`、`BlogColumn/Article/Tag` | 支撑内容生产主链路；涉及多模型关联和作者权限。 | 保持现有服务端渲染写作流程；任何权限或发布规则变更先补 CR 和测试。 |
| 评论、点赞、收藏基础互动 | `comment`、`CommentService`、`ArticleService`、`Comment/Like/Favorite` | 支撑轻互动闭环；点赞和收藏依赖唯一约束。 | 保留当前数据关系；若只补展示规则，不默认改模型。 |
| 后台仪表盘、文章、用户、分类、标签、专栏、评论治理 | `dashboard`、`admin`、各后台蓝图、后台模板 | 支撑管理员治理链路；后台路由目前分散在多个模块中。 | 当前可接受；后续若后台范围扩大，可评估后台路由边界局部整理。 |
| Flask 工厂函数、Blueprint、SQLAlchemy、SQLite、密码哈希、权限、CSRF、环境变量、错误页 | `app/__init__.py`、`extensions.py`、`models.py`、`config.py`、模板基座 | 属于架构基座，变更风险高。 | 保持 ADR-002 方案 B，不换栈、不前后端分离、不重新开发。 |

保留类功能的总体影响：

1. 当前架构能承载课程演示主链路，设计重点是补测试和文档追溯，而不是重新设计架构。
2. 保留类功能仍有回归风险，尤其是搜索、权限、发布、评论审核、CSRF 和错误处理路径。
3. 如果后续对保留类功能做体验增强，应优先作为小范围 CR，不应扩大成无关重构。

## 4. 完善类功能对当前架构的影响

完善类功能包括 F011、F012、F020、F025、F033、F036、F037、F048、F049、F050。这些功能不是简单删除对象，也不应默认立即改代码，应先补规则、测试和设计说明。

| 功能 | 当前问题 | 可能影响模块 | 设计影响 |
| --- | --- | --- | --- |
| F011 修改密码能力 | 代码能力与 README 旧口径可能冲突。 | `user`、账号安全说明、测试报告 | 主要是文档和测试口径影响；不构成架构变更。 |
| F012 个人中心、存档、阅读、交流页面 | 最近阅读当前使用收藏替代，阅读页和交流页边界不清。 | `user`、个人空间模板、`Favorite`、可能的 `ReadingHistory` | 若采纳真实最近阅读，可能新增模型、路由和写入时机设计。 |
| F020 收藏语义 | 收藏被用作最近阅读替代展示会造成语义混淆。 | `comment`、`ArticleService.toggle_favorite()`、`Favorite`、个人阅读页 | 若拆分收藏与阅读记录，可能影响数据语义和页面展示。 |
| F025 专栏启用/禁用规则 | 禁用专栏后的前台列表、详情和关联文章访问规则需确认。 | `column`、`public`、文章详情、后台专栏管理 | 主要影响查询条件和展示规则；暂不默认改数据库。 |
| F033 AI 日志闭环 | 基础日志存在，采纳结果、问题标记和后台查看未闭合。 | `AiLog`、`ai`、写作页、后台 AI 页面 | 若新增字段写入、采纳流程或后台列表，可能影响模型、接口和模板。 |
| F036 演示数据初始化 | 脚本存在，但数据规模和执行结果未确认。 | `scripts/`、SQLite、README、测试报告 | 先确认演示数据标准；若脚本不足再立 CR。 |
| F037 自动化或 E2E 测试 | 脚本存在，但当前执行结果未确认。 | `test_e2e.py`、测试报告、演示路径 | 影响质量保护，不直接影响业务架构。 |
| F048 视觉一致性 | CSS 和模板存在，但未做本次视觉验收。 | `main.css`、`v041.css`、`v041.js`、各模板 | 可能触发 CSS/JS 分层或模板小修，但应基于验收缺陷。 |
| F049 README 和启动指南 | 启动、初始化和 AI 配置未完成当前验证。 | README、配置说明、脚本 | 主要是文档和复现路径影响，不默认改配置。 |
| F050 文档链路 | 正式需求、概要设计、测试、Review、AI 协作记录仍需补齐。 | `docs/`、CR、ADR、测试记录 | 治理流程影响；若改变流程规则可能需要 ADR。 |

完善类功能的总体影响：

1. 最可能触发局部设计调整的是 F012/F020、F025、F033、F048。
2. 最可能触发数据库变更的是 F012/F020 和 F033。
3. F036/F037/F049/F050 优先补验证和文档，不应在没有执行结果时声称已经通过。

## 5. 推迟类功能对当前架构的影响

推迟类功能包括 F026-F032，主要是 AI 写作辅助和 AI 智能搜索。它们有接口或计划价值，但当前不应替代稳定主链路。

| 功能范围 | 当前状态 | 对架构的影响 | 后续设计前提 |
| --- | --- | --- | --- |
| F026-F031 AI 写作辅助 | 摘要、标签、润色、问答、大纲、标题建议接口存在或待验证。 | 依赖 `AIService`、写作页前端、AI 日志、环境变量和异常处理。 | 先验证 API Key、成功调用、超时、失败提示、返回格式和结果采纳方式。 |
| F027 AI 标签推荐 | 可能影响标签来源和标签创建规则。 | 若允许自动创建标签，会影响 `Tag`、`ArticleTag` 和后台标签治理。 | 先确认只推荐已有标签，还是允许自动创建新标签。 |
| F032 AI 智能搜索 | 接口存在，但真实调用、入口、角色、降级和性能需确认。 | 影响 `AIService.smart_search()`、`public` 搜索体验、`v041.js` 和搜索结果模板。 | 传统搜索 F007 必须继续作为稳定 fallback，不得被 AI 搜索替代。 |

推迟类功能的总体影响：

1. 当前架构已经提供 AI 集中封装点，暂不需要换栈或引入新架构。
2. AI 能力的主要风险是外部依赖、失败降级、响应时间、日志完整性和演示可重复性。
3. 如果后续要引入多 Provider、流式输出、异步队列、向量检索或复杂成本审计，应重新评估 ADR，不应直接塞入当前 AIService。

## 6. 删除/暂不纳入功能对当前架构的影响

删除/暂不纳入功能当前以 F035 AI 阅读页提示能力为代表，同时包括功能矩阵中明确排除的大型平台能力和复杂 AI 架构。

| 范围 | 当前判断 | 对架构的影响 |
| --- | --- | --- |
| F035 AI 阅读页提示能力 | 当前只是后续提示，不纳入当前验收和近期实现范围。 | 不新增阅读助手模型、接口、日志流程或页面闭环；阅读页仍按文章阅读主链路处理。 |
| 付费、广告、热榜、私信、关注体系、复杂推荐、问答社区 | 当前无完整需求和代码事实，不纳入当前基线。 | 不新增交易、消息、推荐、关注关系或社区问答数据模型。 |
| 多 Provider、流式输出、向量检索 | 当前不作为默认 AI 架构。 | 不引入任务队列、向量库、搜索引擎或多 Provider 插件体系。 |
| 前后端分离、微服务、重写 v1.0 | 与 ADR-002 当前口径不一致。 | 当前不拆分为独立前端、API 服务或微服务。 |

删除/暂不纳入功能的设计意义：

1. 保持当前架构边界清晰，避免把课程实践系统扩大成生产级平台。
2. 降低数据库模型、权限体系、页面流程和测试范围的无谓扩张。
3. 为答辩保留清楚口径：当前优先证明已实现主链路、测试和文档追溯，而不是堆叠未闭环功能。

## 8. 可能需要数据库变更的功能

以下功能若后续进入实现，可能影响数据库结构或数据语义：

| 功能 | 可能数据库影响 | 是否当前建议立即修改 |
| --- | --- | --- |
| F012 真实最近阅读 | 可能新增 `ReadingHistory` 模型，记录 `user_id`、`article_id`、阅读时间和去重策略。 | 否。先确认产品边界。 |
| F020 收藏与最近阅读拆分 | 可能保留 `Favorite` 语义，并新增阅读历史表；也可能只调整展示口径不改库。 | 否。需与 F012 一并确认。 |
| F027 AI 标签推荐自动创建 | 若自动创建标签，可能改变 `Tag` 去重、创建来源和治理字段。 | 否。先确认是否允许自动创建。 |
| F033 AI 日志闭环 | 可能补充或启用 `adopted_result`、`is_adopted`、`problem_found` 等字段写入流程，必要时新增字段。 | 否。先补日志闭环需求和设计。 |
| F036 演示数据规模调整 | 通常不改表结构，但会影响初始化数据和默认账号。 | 否。先确认演示数据标准。 |
| F039 模型字段说明和 ER 图 | 文档补齐不改库；若发现模型无法支撑确认需求，才可能变更。 | 否。当前只建议补设计说明。 |
| F040 数据库切换 | 从 SQLite 切换到其他数据库会影响配置、迁移和部署。 | 否。ADR-002 当前不建议换库。 |

数据库变更原则：

1. 没有确认后的 CR、设计说明、测试计划和必要 ADR，不进入模型或表结构修改。
2. 当前 SQLite 继续作为本地开发和课程演示数据库，不能默认升级为生产数据库方案。
3. 若后续新增模型或字段，应补迁移或初始化策略，避免只修改模型但无法复现数据库。

## 9. 可能需要新增 ADR 的变更

| 变更方向 | 关联功能或候选变更 | 需要 ADR 的原因 |
| --- | --- | --- |
| 引入真实 ReadingHistory | F012、F020、CR-CAND-002、CR-CAND-003 | 涉及新增模型、数据语义拆分、写入时机和页面边界。 |
| AI 标签自动创建或标签治理规则变化 | F027、CR-CAND-009 | 影响标签数据来源、后台治理和内容组织边界。 |
| AI 智能搜索升级为稳定主链路或改变搜索策略 | F007、F032、CR-CAND-010 | 涉及传统搜索与 AI 搜索关系、开放角色、降级、性能和可解释性。 |
| AI 日志采纳闭环和后台查看 | F033、F034、CR-CAND-011 | 可能涉及字段语义、采纳流程、问题标记、统计口径和后台权限。 |
| AI 阅读助手重新纳入 | F035、CR-CAND-012 | 当前为删除/暂不纳入；若重新立项会新增阅读助手流程和 AI 数据流。 |
| 正式治理流程或文档链路规则变化 | F050、CR-CAND-017 | 若改变 CR、ADR、测试、Review 的审批和交付规则，需要决策记录。 |
| 模型拆分、数据库切换或迁移体系引入 | F039、F040、CR-CAND-018、CR-CAND-019 | 影响架构基座、导入关系、部署和回滚。 |
| 大型平台能力或复杂 AI 架构重新纳入 | CR-CAND-020 | 会显著扩大产品边界和技术边界。 |

ADR 判断口径：

1. 只改文档、补测试记录或修正文案，通常不需要 ADR。
2. 影响模型、数据库、架构边界、搜索策略、AI 服务策略或治理流程的变更，应先写 ADR。
3. 新 ADR 不应推翻 ADR-002；除非明确重新评估技术路线，否则仍以方案 B 为上位约束。

以下变更若进入实现，必须先补测试保护或验收记录：

| 变更范围 | 必须保护的路径 |

| 评论和互动 | 评论提交待审核、审核、隐藏、删除、点赞、取消点赞、收藏、取消收藏、防重复提交。 |
| 专栏、分类、标签治理 | 专栏启用禁用、专栏删除关联、分类删除关联、标签删除关联、空状态和重复名称处理。 |
| F012/F020 个人空间和阅读历史 | 收藏列表、最近阅读、存档、交流页、数据语义迁移或并存展示。 |
| F026-F032 AI 能力 | 无 Key 提示、配置 Key 成功调用、超时、HTTP 错误、JSON 异常、AI 搜索 fallback、日志写入。 |
| F033 AI 日志闭环 | 采纳、取消采纳、问题标记、后台查看、统计口径和权限边界。 |
| F048 视觉一致性 | 首页、文章详情、搜索页、写作页、个人中心、后台仪表盘等样本截图或手工验收。 |
| F036/F049 启动和初始化 | 依赖安装、数据库初始化、演示数据、默认管理员、AI 环境变量说明和复现步骤。 |

测试保护原则：

1. 不把历史“全部通过”写成当前通过，除非本阶段已经重新执行并记录。
2. 对高风险变更，至少先有手工验收路径；最好补自动化或 E2E 保护。
3. 测试记录应区分通过、失败、未执行和需人工确认。

## 11. 当前不建议立即改代码的原因

当前不建议立即改代码，原因如下：

1. 本阶段目标是产品重新基线化和工程治理，不是 v0.6 功能开发。
2. ADR-002 已采纳方案 B，但方案 B 明确要求测试保护、需求确认和必要 ADR，不等于当前直接重构。
3. 多数问题仍处在候选 CR 阶段，尚未完成产品确认、设计说明和验收标准。
4. 当前启动、初始化、E2E、AI 真实调用和视觉验收结果未在本文档范围内重新验证。
5. F001-F025 主业务闭环已存在，缺少测试保护时改动代码容易破坏课程演示主链路。
6. 可能涉及数据库的功能尚未确认，例如 ReadingHistory、AI 日志闭环和标签自动创建。
7. AI 相关问题主要是真实调用验证、失败降级、日志和采纳规则，不需要通过换栈或重写解决。
8. 当前禁止无关重构、换栈、删除旧文档、自动同步外部目录和伪造测试结果。

## 13. 阶段性结论

产品重新基线化对当前软件设计的主要影响不是“必须立即重写系统”，而是把后续变化分成四类处理：

1. 保留类功能继续作为当前产品基线，重点补测试和文档追溯。
2. 完善类功能先补产品规则、设计说明和测试保护，再判断是否需要代码或数据库变更。
3. 推迟类功能尤其是 AI 写作和 AI 搜索，应先完成真实调用、降级和日志验证，不替代传统稳定链路。
4. 删除/暂不纳入功能继续排除在当前验收和近期实现外，避免扩大架构边界。

因此，当前应继续遵守 ADR-002 方案 B：保留现有 Flask + Jinja2 + SQLAlchemy + SQLite 单体架构，在明确需求、测试保护和必要 ADR 前提下做受控局部重构。本文不提出立即改代码、不提出已经完成的重构、不提出数据库已变更结论。
