## 3. 每个业务模块内部通常有什么

大多数业务模块都有类似结构：

```text
app/某模块/
├── __init__.py
├── routes.py
└── services.py
```

| 文件 | 通俗解释 |
| --- | --- |
| `routes.py` | “门牌和前台接待”：定义 URL，接收浏览器请求，判断登录权限，然后决定返回页面还是 JSON。 |
| `services.py` | “办事员或业务规则”：处理可复用的查询、校验、创建、更新、删除等逻辑。 |
| `__init__.py` | Python 包标识文件，让目录能被导入。 |

不是每个模块都完全一样。例如 `admin/` 主要是权限装饰器和后台入口，`dashboard/` 负责后台统计，`ai/` 的 service 负责外部 AI 调用。

## 8. 模块边界注意事项

1. 后台路由不是集中在一个 `admin/` 模块里，而是分散在文章、分类、标签、评论、专栏、用户、AI 等模块中，用 `admin_required()` 统一保护。
2. 点赞和收藏入口在 `comment/routes.py`，但真正的业务逻辑在 `ArticleService.toggle_like()` 和 `ArticleService.toggle_favorite()`。
3. 普通用户写文章的路由在 `user/routes.py`，但创建和更新文章的业务逻辑在 `article/services.py`。
4. 公开专栏和我的专栏都在 `column/routes.py`，同一个模块同时服务游客、登录用户和管理员。
5. AI 模块既有后台状态页，也有写作接口和公开 AI 搜索接口，状态需要拆开理解。
