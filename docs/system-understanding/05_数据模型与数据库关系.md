# 数据模型与数据库关系

生成日期：2026-07-02

本文从 DBA Agent 视角解释当前数据模型、表关系、字段语义和风险。本文只描述当前 `app/models.py` 和相关脚本事实，不新增模型，不修改数据库，不执行迁移。

## 1. 数据库总体口径

当前系统使用 SQLAlchemy 模型管理数据，默认数据库是 SQLite 文件：

```text
instance/personal_blog.sqlite
```

配置位置是 `config.py`：

```text
SQLALCHEMY_DATABASE_URI = sqlite:///.../instance/personal_blog.sqlite
```

SQLite 适合本地开发、课程实践和轻量演示。当前文档不把它夸大为生产级高并发数据库方案。

## 3. 主要关系图

```text
User 1 ── * Article
User 1 ── * BlogColumn
BlogColumn 1 ── * Article
Category 1 ── * Article
Article * ── * Tag，通过 ArticleTag
Article 1 ── * Comment
User 1 ── * Comment
User * ── * Article，通过 Like
User * ── * Article，通过 Favorite
Article 1 ── * AiLog
```

通俗解释：

1. 一个用户可以写多篇文章，也可以创建多个专栏。
2. 一篇文章属于一个分类，可以属于一个专栏，也可以有多个标签。
3. 标签和文章是多对多关系，所以需要 `ArticleTag` 中间表。
4. 评论、点赞、收藏都围绕文章发生。
5. AI 日志可以关联某篇文章，也可以不关联文章，例如 AI 搜索日志。

## 4. `User` 用户模型

| 字段 | 含义 |
| --- | --- |
| `username` | 用户名，唯一。 |
| `email` | 邮箱，唯一。 |
| `password_hash` | 密码哈希，不保存明文。 |
| `nickname` | 显示昵称。 |
| `role` | 角色，当前通过 `admin` 区分管理员。 |
| `status` | 状态，`active` 表示可登录。 |
| `bio` / `avatar` | 个人简介和头像地址。 |
| `created_at` / `updated_at` | 创建和更新时间。 |

模型方法：

| 方法或属性 | 含义 |
| --- | --- |
| `set_password()` | 用 `pbkdf2:sha256` 生成密码哈希。 |
| `check_password()` | 校验用户输入密码。 |
| `is_active` | 当前实现为 `status == "active"`。 |
| `is_admin` | 当前实现为 `role == "admin"`。 |

风险与确认：

1. 管理员不能被禁用的逻辑在后台用户路由中处理。
2. 禁用用户后其已发布文章、评论、专栏前台如何展示，需要人工确认和测试。

## 5. `Article` 文章模型

| 字段 | 含义 |
| --- | --- |
| `title` | 文章标题。 |
| `slug` | URL 中使用的唯一标识。 |
| `summary` | 摘要。 |
| `content` | 正文。 |
| `status` | `draft` 或 `published`。 |
| `user_id` | 作者用户。 |
| `column_id` | 所属专栏，可为空。 |
| `category_id` | 所属分类，不能为空。 |
| `author` | 作者展示名。 |
| `view_count` | 阅读量。 |
| `like_count` | 点赞计数。 |
| `favorite_count` | 收藏计数。 |
| `published_at` | 发布时间。 |

状态常量：

| 常量 | 含义 |
| --- | --- |
| `ARTICLE_STATUS_DRAFT` | 草稿。 |
| `ARTICLE_STATUS_PUBLISHED` | 已发布。 |

风险与确认：

1. 文章点赞和收藏既有关系表，也有计数字段；如果未来手动改库或脚本异常，计数可能和实际关系数不一致。
2. 删除分类、标签、专栏、文章时的关联影响需要测试确认。
3. 禁用专栏后，文章详情是否仍可访问需要需求澄清。

## 6. 分类、标签和专栏

### 6.1 `Category`

分类是一对多关系：一个分类下有多篇文章。当前字段包括 `name`、`description`、`sort_order`。

风险：删除已有文章使用中的分类时，当前行为需测试确认。

### 6.2 `Tag` 和 `ArticleTag`

标签是多对多关系：一篇文章可有多个标签，一个标签也可属于多篇文章。`ArticleTag` 使用 `article_id` 和 `tag_id` 作为复合主键。

风险：删除标签会影响文章标签展示，需测试确认。

### 6.3 `BlogColumn`

专栏属于用户，文章可选属于专栏。专栏有 `status` 字段，默认 `active`。

风险：F025 虽然有启用/禁用专栏能力，但禁用后前台列表、详情和文章访问规则仍需确认。

## 7. 评论、点赞和收藏

### 7.1 `Comment`

评论属于文章，可选关联用户。评论状态包括：

| 状态 | 含义 |
| --- | --- |
| `pending` | 待审核。 |
| `approved` | 已通过。 |
| `hidden` | 已隐藏。 |

当前评论提交流程默认创建 `pending` 评论，管理员在后台审核、隐藏或删除。

### 7.2 `Like`

点赞表记录用户和文章的关系，并有唯一约束：

```text
user_id + article_id 唯一
```

这表示同一个用户不能对同一篇文章重复点赞。

### 7.3 `Favorite`

收藏表与点赞类似，也有唯一约束：

```text
user_id + article_id 唯一
```

重要边界：当前个人中心的 `recent_reads` 使用收藏记录临时代替。收藏仍应按收藏功能理解，不能写成真实阅读历史。

## 8. AI 日志 `AiLog`

| 字段 | 当前含义 |
| --- | --- |
| `article_id` | 可选关联文章。 |
| `scene` | AI 场景，如 summary、tags、polish、smart_search。 |
| `input_text` | 输入内容。 |
| `ai_output` | 输出内容或错误信息。 |
| `adopted_result` | 采纳结果字段存在。 |
| `is_adopted` | 是否采纳字段存在，默认 False。 |
| `problem_found` | 问题标记字段存在。 |
| `created_at` | 日志创建时间。 |

当前代码事实：

1. `app/ai/routes.py` 的 `_log()` 会写入 `scene`、`input_text`、`ai_output` 和可选 `article_id`。
2. 当前未见完整前端或后台流程写入 `adopted_result`、`is_adopted`、`problem_found`。
3. 管理员 `/admin/ai` 是配置状态页，不是 AI 日志后台治理页。

因此 F033 只能写为“基础日志存在，闭环需完善或确认”。

## 11. DBA 视角风险清单

1. `ReadingHistory` 不存在，不能把最近阅读写成真实阅读历史。
2. `AiLog` 有闭环字段，但缺少完整采纳/问题标记流程。
3. `Like`、`Favorite` 有唯一约束，同时文章有计数字段，需防止计数和关系表不一致。
4. 删除分类、标签、专栏、文章时的关联影响需测试确认。
5. 禁用用户或专栏后的前台可见性规则需人工确认。
6. SQLite 适合课程演示，未来若变更数据库或引入迁移工具，需要 ADR 判断。
7. 演示数据脚本规模较大，当前执行结果和数据库实际数据量需真实记录。
