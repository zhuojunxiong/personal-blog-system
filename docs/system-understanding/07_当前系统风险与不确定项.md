# 当前系统风险与不确定项

生成日期：2026-07-02

本文汇总当前系统理解过程中发现的风险、事实不清、测试缺口、文档冲突和后续人工确认事项。本文不授权改代码；疑似缺陷只能记录为风险或后续 CR 输入。

## 1. 风险分级说明

| 等级 | 含义 |
| --- | --- |
| 高 | 可能影响 v1.0 启动、演示、测试、答辩或事实准确性。 |
| 中 | 不一定阻塞交付，但需要澄清规则、补测试或校准文档。 |
| 低 | 对当前主链路影响较小，可作为后续优化或记录。 |

## 5. 当前明确不应纳入 v1.0 实现的范围

| 范围 | 原因 |
| --- | --- |
| 真实 `ReadingHistory` 模型和写入规则 | 涉及新增表、写入时机、隐私和页面语义，需独立 CR 和 ADR 判断。 |
| AI 日志采纳闭环完整实现 | 涉及字段语义、前端采纳动作、后台查看和统计，需独立 CR。 |
| 将 AI 搜索升级为主入口 | 当前传统搜索 F007 是稳定主入口，AI 搜索需先完成验收。 |
| 多 Provider、流式输出、向量检索 | 会扩大 AI 架构复杂度，不符合当前收束目标。 |
| 关注、私信、热榜、复杂推荐、问答社区 | 超出博客课程交付主链路。 |
| 付费、广告、会员、商业化 | 与当前课程交付无直接关系。 |
| 前后端分离、微服务、任务队列、换数据库 | 与 ADR-002 方案 B 不一致，需未来 ADR。 |
| 大范围 UI 重做 | v1.0 只做视觉验收和必要问题记录。 |

## 7. 项目负责人需要人工确认的问题

1. 本轮是否确认只新增系统理解文档，不修改业务代码。
2. v1.0 是否以“课程交付收束”为主，而不是继续扩展功能。
3. AI 真实调用是否必须纳入 v1.0 答辩演示，还是只做接口存在和降级说明。
4. 是否接受当前个人中心阅读页暂按收藏口径说明。
5. 禁用专栏和禁用用户后，前台内容展示规则应如何定义。
6. 是否需要在后续 CR 中补齐 400 错误页或错误路径测试。
7. README、启动指南、版本口径是否由后续文档校准任务处理。
8. 是否确认 `N006`、`N007`、`N011` 等增强不直接进入当前代码实现。
9. 是否确认继续遵守 ADR-002 方案 B。
