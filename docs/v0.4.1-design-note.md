# v0.4.1 Design Note

## Version Goal

v0.4.1 is a low-risk refinement over v0.4. It keeps the Flask + Jinja2 server-rendered architecture and focuses on page layout, interaction flow, visual consistency, protected routes, empty/error states, and AI placeholders.

The product philosophy is:

> 让写作回到思考，让阅读回到平等。

## Difference From v0.4

- `/` changed from content aggregation to the product philosophy landing page.
- The original aggregation home is preserved at `/discover`.
- `/home`, `/search`, and `/articles/<slug>` form a quieter public reading chain.
- Auth pages use the v0.4.1 visual system and preserve Flask-Login behavior.
- `/profile` is now the real personal study page; `/me` redirects to `/profile`.
- Personal space, writing, author, column, and status pages share the v0.4.1 visual language.
- AI features are placeholders only and do not call external AI services.

## Visual System

The v0.4.1 interface uses a quiet paper-like style:

- light warm paper background
- ink-like text
- soft separators
- restrained rounded cards
- serif headings
- low visual noise
- writing and reading first

The main stylesheet is `app/static/css/v041.css`. v0.4.1 page styles use explicit namespaces such as `landing-page`, `home-page`, `search-results-page`, `article-reading-page`, `auth-page`, `profile-shell`, `write-page`, and `public-profile-page`.

## Backend Route Adjustments

- `public.index` renders the new landing page.
- `public.home` renders the search home.
- `public.search` supports keyword search and pagination.
- `public.article_detail` keeps `/articles/<slug>` and renders the reading space.
- `user.profile_home` renders `/profile`.
- `/me` redirects to `/profile`.
- Writing routes reuse existing `ArticleService.create` and `ArticleService.update`.
- Legacy edit route `/my/articles/<id>/edit` remains available.

## Authentication Chain

Authentication continues to use Flask-Login. Protected routes redirect to `/login?next=...`. Login accepts username or email, and success returns to `next` when safe. Registration keeps the passcode field as a future UI placeholder and does not enforce it.

## Personal Space Chain

The personal space includes:

- `/profile`: start writing, archive summary, reading trace summary
- `/profile/archive`: user columns and articles
- `/profile/reading`: favorites and lightweight recent-reading placeholder
- `/talk`: lightweight comment-based communication center
- `/settings`: password change, logout confirmation, future public display placeholder

No complex messaging system is added.

## Writing Chain

The writing page includes:

- title input
- summary input
- content textarea
- category, column, and tag settings
- save draft
- publish article
- saved/unsaved status
- unsaved-leave warning
- right-side AI Q&A placeholder

Draft and publish states reuse existing `Article.status` values.

## Author And Column Pages

`/users/<id>` shows public author information, published articles, and columns. It does not include following, private messages, or social metrics.

`/columns/<id>` shows column name, description, creator, article count, and published articles. It reuses the existing `BlogColumn` model.

## Status Pages

403, 404, and 500 pages are friendly v0.4.1 pages. They avoid stack traces and provide simple navigation back to home, search, personal space, or previous page.

## AI Placeholder Policy

AI features are UI-only in v0.4.1:

- home AI search label uses normal keyword search
- search summaries use existing article summaries or content excerpts
- article AI reading prompt shows a future-version message
- writing AI Q&A appends a placeholder message

No external AI API, SDK, API key, streaming, vector database, or remote request is added.

## Test Results

The final verification should include Python syntax checks, Jinja template loading, Flask test client route checks, protected route redirects, writing save/publish flow with a writable test database, and boundary checks for AI/framework/database changes.

Codex sandbox may report SQLite readonly when writing to `instance/`. This is a sandbox permission limitation. Local real-permission testing confirmed `/write` can save drafts, edit, and publish against the real SQLite database.

## v0.5 Suggestions

For v0.5, organize JSON APIs for future frontend separation and AI integration:

- article search API
- article reading API
- writing draft/publish API
- profile archive API
- reading history API
- comment/talk API
- AI placeholder API contract

Keep Flask/Jinja as the stable web experience until the API layer is clean enough to support future React/Vue or mobile clients.
