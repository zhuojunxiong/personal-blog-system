# v0.4.1 Implementation Rules

## Technical Boundary

The project is a Flask + Jinja2 server-rendered web app. v0.4.1 must continue using:

- Flask routes
- Jinja2 templates
- Flask-Login
- Flask-SQLAlchemy
- SQLite
- CSS and small native JavaScript

## Do Not Migrate Frameworks

Do not introduce React, Vue, FastAPI, or a separate frontend app in v0.4.1. Future frontend separation should wait until the JSON API layer is planned and tested.

## Do Not Connect Real AI

AI features are placeholders only. Do not add:

- external AI SDKs
- API keys
- remote model requests
- streaming output
- vector database
- semantic search infrastructure

## Do Not Make Large Database Changes

v0.4.1 reuses existing models. Do not add complex tables for messages, reading analytics, AI logs, social relationships, or permissions unless a later version explicitly plans them.

## Reuse v041 Assets

New v0.4.1 pages should reuse:

- `app/static/css/v041.css`
- `app/static/js/v041.js`
- shared templates under `app/templates/shared/`

Use page namespaces to avoid polluting admin and legacy pages.

## Route Rules

- Keep old routes compatible.
- Prefer redirects or shared templates over deleting routes.
- Use Flask-Login for protected pages.
- Keep `/articles/<slug>` as the article reading route.

## Template Rules

- Do not paste reference UI images as static pages.
- Use real HTML forms, links, buttons, inputs, and modals.
- Provide empty/error states for data lists.
- Keep public pages separate from personal pages.

## CSS Rules

- Keep styles in `v041.css`.
- Use namespaces like `public-profile-page`, `write-page`, `profile-shell`.
- Avoid global overrides that affect admin pages.
- Keep the visual style quiet, paper-like, and writing/reading centered.

## JavaScript Rules

- Use native JS only for small interactions.
- Keep behavior progressive and non-critical where possible.
- AI interactions should show placeholder messages only.

## Future Evolution

v0.5:

- Define JSON API contracts.
- Add reading history model if needed.
- Improve writing draft workflow.
- Prepare AI API boundary without connecting providers by default.

v1.0:

- Stabilize roles, permissions, content moderation, and public profile editing.
- Add tests and deployment documentation.

v2.0:

- Consider frontend separation only after API maturity.
- Consider a real editor and richer reading history.

v3.0:

- Add real AI integration behind explicit provider configuration and safe key management.
